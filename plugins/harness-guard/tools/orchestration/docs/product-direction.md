# 공통 개발 기반 안의 개발 조정

Team Harness 한 제품에서 회사의 기술·품질 기준과 개발 조정을 제공한다. 이 모듈은 선택형 workflow이며 core 정책을 복제하지 않는다. 현재 회사 공통 기준은 아직 채택되지 않았다. Harness의 제안 기준과 실제 회사 채택을 구분한다.

## 공통 기반과 프로젝트별 적용

| 위치 | 책임 |
| --- | --- |
| Team Harness core | GitHub·CI·리뷰·릴리즈·증거·감사와 복구 기준 |
| Team Harness 개발 조정 | 필요한 역할 선택, 작업 소유권, 인계, 진행, 현재 후보 검증과 인수 |
| 개발 제품 저장소 | 제품 코드, 기술 선택, AGENTS.md, 요구·설계·이슈·실행 상태·검증 증거 |
| Codex·Claude Code 등 실행 도구 | native 모델 실행, context, subagent, 권한과 격리 |

직무별로 에이전트를 상시 배치하지 않는다. 백엔드·프론트엔드·인프라를 한 개발자가 다루더라도 변경 경계와 필요한 검사를 명확히 하는 것이 목적이다. 공유 지침을 제품 특성에 맞춰 연결하며 전역 설정을 자동 수정하지 않는다.

## Team Harness에 이미 있는 기술 기준

Team Harness 저장소의 `docs/stack-guide.md`, `docs/architecture-infra.md`, `docs/code-review.md`, `docs/ai-collaboration.md`와 `templates/rules/stacks/`가 원본이다. 제품에 배포된 `.claude/rules/*.md`는 해당 제품 AGENTS.md의 명시적 읽기 지침과 연결한다. 이 패키지에 스택 기준 사본을 만들지 않는다. 실제 사용 시 현재 source ref·제품 채택 버전·적용 규칙을 확인한다.

## 영역을 넘는 작업에서 확인할 것

| 영역 | 직접 소비자와 확인 항목 |
| --- | --- |
| 백엔드 | API 계약·권한·데이터·마이그레이션·호환성과 실패 응답 |
| 프론트엔드 | API 소비·오류/빈 상태·접근성·사용자 흐름·빌드 |
| 인프라 | 대상 환경·비밀 관리·최소 권한·관측·복구·실제 적용 권한 |

영역별 이름만으로 일을 나누지 않는다. 이번 변경에 필요한 원본·소유 경로·수용 기준만 제품 기록에 남긴다. 코드 검사와 운영 적용, 선언 검사와 실제 권한 강제, 로컬 표본과 회사 전체 도입은 서로 다른 완료 조건이다.
