# 로컬 Spring Boot+Vue 검사 시작 구성

상태: #462 구현 진행. 제품 순서는 [제품 방향](../product-direction.md), 작업 상태는
[이슈 #462](https://github.com/grinvi04/team-harness/issues/462)가 정본이다.

## 목표와 범위

프로젝트마다 백엔드·프론트 검사 순서와 루트 경로 처리를 다시 작성하는 일을 줄인다.
판정은 **소유**다. 이미 준비된 Spring Boot/Gradle + Vue/npm 프로젝트에 검증된 검사 진입점을
추가한다. 신규 앱도 각 프레임워크로 생성하고 검사 설정을 준비한 뒤 같은 경로로 연결한다.
전체 앱·검사 도구 설정 자동 생성, Maven/pnpm/다른 디렉터리 구조 지원, 회사 정책·GitHub·배포·전역
설정 변경은 범위 밖이다. 기존 제품 전용 검사와 데이터는 보존한다.

사용자가 승인한 첫 재사용 시작 구성 범위 안에서 구현한다. 기존 검사 명령과 기준을 재사용하며
설치가 검사 자체를 실행하거나 통과 결과를 보증하지 않는다.

## 수용 기준

- **AC-1 미리보기:** `node scripts/setup-local.mjs --project <경로>`는 준비 조건을 확인하고
  생성할 `scripts/check-harness.sh`와 실행 순서를 보여준다. 프로젝트 파일·Git·네트워크를 변경하지 않는다.
- **AC-2 적용:** `--apply`에서만 검사 파일 하나를 생성한다. 다른 작업 디렉터리와 공백이 있는 경로에서도
  동작한다. AGENTS.md·기존 check-local.sh·앱 설정·데이터·원격을 변경하지 않는다.
- **AC-3 거부:** 잘못된 옵션, 존재하지 않는 프로젝트, Gradle/Vue/lockfile/필수 npm 명령 누락,
  기존 목적 파일(일반 파일·디렉터리·끊어진 링크 포함), scripts 디렉터리의 링크를 거부한다.
  생성 전에 모든 조건을 검사하며 기존 파일을 덮어쓰지 않는다. 동시 악성 파일시스템 변경에 대한
  보안 격리 도구가 아니며, 사용자가 관리하는 로컬 프로젝트에서 실행한다.
- **AC-4 검사:** 생성 파일은 실행 위치와 무관하게 프로젝트 루트에서 backend의 `./gradlew check bootJar`,
  frontend의 `npm ci`, `type-check`, `lint`, `test:unit`, `build`, 프로젝트에 설치된 Playwright의
  Chromium 준비, `test:e2e`를 순서대로 실행한다. 어느 단계든 실패하면 이후 단계와 성공 표시 없이
  비정상 종료한다. 누락된 검사를 `--if-present`로 건너뛰지 않는다.
- **AC-5 실제 연결:** 로컬 샘플의 격리 사본에 적용하고 실제 제품 검사를 실행한다. 준비가 빠진 경우와
  검사 실패 시 중단도 확인한다. 원본 샘플의 파일·DB·원격은 그대로 보존한다.
- **AC-6 안내:** README·온보딩·제품 로드맵과 이 체크리스트를 실제 결과에 맞춘다. 이 경로는 검사 연결만
  재사용하며 테스트 자체의 충실도, 제품 전용 영속성 검사·이미지 복원, 모든 스택 지원을 보장하지 않는다.

## 접근과 검증

- 표준 원본: `templates/rules/stacks/java.md`, `vue.md`, 기존 Spring+frontend CI 템플릿.
  로컬 샘플의 check-local.sh에서 공통 검사 순서만 가져온다. 제품 전용 이미지 복원·영속성 검사는 가져오지 않는다.
- `scripts/setup-local.mjs`: Node 기본 파일 API로 준비 조건·쓰기 대상 검사, 기본 미리보기와 명시적 적용.
  목적 파일은 exclusive create로 작성한다. 외부 패키지·Git·네트워크 호출은 없다.
- `templates/local/spring-vue/check-harness.sh`: 짧고 독립적으로 복사 가능한 Bash 검사 진입점.
  패키지 설치와 제품 명령 실행은 사용자가 생성 파일을 실행할 때만 수행한다.
- `tests/local-setup-test.mjs`: AC-1~4의 CLI 출력·파일 불변·정상 순서·실패 중단을 검증한다.
  명령 실행 경계는 임시 도구 대역으로 검사하고, AC-5는 별도 실제 제품 실행으로 확인한다.
- 기존 CI quality에 위 검사를 추가하고 전체 품질 검사 및 다른 인스턴스의 최종 검토를 수행한다.

승인된 Luna/max worker는 검사 템플릿 파일만 구현한다. 최종 검증자는 구현에 참여하지 않는다.

## 검증 결과

- 2026-09-22: 동작 미구현에 의한 assertion RED 8개 → 구현 후 8개 통과.
  구현 중 spec/test 해시 불변을 확인한 뒤 부모가 진행 체크리스트만 갱신했다.
- 로컬 샘플의 커밋된 소스를 공백 경로의 임시 사본에 풀어 미리보기·적용·실제 검사를 수행했다.
  Gradle 9개 작업이 새로 실행됐고 타입·lint·단위 49개·빌드·E2E 18개가 통과했다.
  실제 Gradle check를 의도적으로 실패시키는 임시 입력에서도 frontend 진입·성공 표시 없이 종료했다.
  원본 샘플의 추적 파일·로컬 DB 해시와 원격 없음 상태를 보존했다.
- 이 시험은 공통 검사 연결의 첫 스택 표본이다. 제품 전용 영속성·이미지 복원 검사를 대체하지 않으며,
  전체 품질·독립 검토·PR·정식 릴리즈 상태는 각 원본 증거를 확인한 뒤 갱신한다.
