# 재설계: 이전과 검증 순서

상태: 사용자 승인된 M1–M5 구현 순서. 현재 단계·결과는 [실행 기록](execution.md)을 따른다.
현재 1.0.0 후보와 기존 dirty 변경·시험·과거 태그를 보존한다. 전면 reset·파일 일괄 삭제로 시작하지 않는다.

## 1. 이전 원칙

- 기능 이름이 아니라 책임·직접 소비자·공개 동작을 기준으로 옮긴다.
- 정상/거부/오류/복구의 기존 핵심 계약은 유지하고 새 경로에서 동등하게 확인한다.
- 기존 경로를 지우기 전에 새 경로·이전 안내·반례·복구를 준비한다.
- 소비 저장소·전역 설정·원격 보호는 설계 변경만으로 자동 갱신하지 않는다.
- 공개 플러그인을 분할하거나 새 task/runtime/권한 계층을 설치하지 않는다.
- 기존 “보편 환경 인수”와 최신 A/B/C의 제한 PASS는 당시 결과로 보존한다.

## 2. 작업 순서와 완료 기준

| 단계 | 작업 | 완료 기준 | 다음 단계 조건 |
|---|---|---|---|
| M0 기준 확정 | 제품 약속·지원 범위·R1–R7·제외·유지 동작·이전 범위 확정 | 독립 설계 검토 반영과 사용자 설계 선택; 구현 승인 범위 명확 | 기준 확정 전 구조 변경 착수 금지 |
| M1 평가 구조 | 기존 QA 판정 코드 대조, 일회성 관찰기의 재사용 가능한 최소 이전, 결과 집계 단일화 | 캐시 생성/삭제·추가 파일·누락·stale·첫 실패 반례가 실제 실패하고 정상 통과 | 평가기 검출력 확인 |
| M2 프로젝트 연결 | 기존 repo 점검·preview/apply·자산 소유 갱신/제거·스택 프로필 정리 | R1; 기존 검사 재사용, 동시 변경 보존·부분 실패·중단 후 수동 복구, 지원/미지원 정확 표시 | 제품 연결 경로 고정 |
| M3 업무와 native 연결 | 공통 계약 최소화, reader/skill 경로 정리, advisory routing 축소·제거 | R2/R4; 실제 공개 진입에서 계약 읽기·범위·검사·인계 관측 | 직접 계약 주입 시험만으로 통과 금지 |
| M4 GitHub 전달 연결 | branch 선택을 제품 선언에 연결, 기존 wrapper·CI·리뷰·복구 경계 대조 | R5; 정상과 누락/조회 실패/후보 이동/복구 시험; 기존 보호 불변 | 원격 실행은 별도 승인된 대상·행동 범위 |
| M5 전체 사용·배포 경계 | README→첫 연결→실제 업무→인계/전달과 artifact→loader→실행 연결 | R3/R6/R7; 구조 문서 지원 표의 필수 행·소스 호환 회귀, 현재 후보 품질·독립 검토·문서 일치 | 미해결 필수 FAIL/UNVERIFIED 0 |
| M6 정식 전달 | 별도 승인된 커밋·PR·release-check·main·태그·역병합·설치·정리 | 각 단계 원격/설치 증거와 복구 확인, 기록 갱신 | 요청한 전달 범위 끝에서 종료 |

M1의 기계 시험과 M3/M5의 실제 모델 실행은 다른 검증이다. 전자의 성공으로 후자를 채우지 않는다.
각 단계가 바꾼 경계만 다시 검증하고, 같은 조건의 무변경 실패를 반복하지 않는다.
독립 검토자가 설계·구현을 수정하지 않는다. 검토에 사용한 원래 요구·후보·증거와 결과를 남긴다.
실제 권한 격리는 관찰한 경우만 주장한다. 역할 이름이나 read-only 요청만으로 기술적 쓰기 차단이라 하지 않는다.

## 3. 책임별 변경 경로

아래는 예상 소유 경로다. 새 파일을 만들기 전에 기존 구현으로 충분한지 확인한다.

| 책임 | 주요 현재 경로 | 이전 전략 |
|---|---|---|
| 평가기 | `tests/fixtures/qa-command-binding.mjs`, `tests/qa-*-test.mjs`, 최근 `.runtime` 관찰 코드 | 알려진 결함을 고정한 최소 모듈을 `tests/acceptance/`에 통합; 기존 판정 중복 제거 |
| 로컬/자산 연결 | `scripts/setup-local.mjs`, `scripts/manage-repo-assets.mjs`, `scripts/new-repo.sh` | 읽기/미리보기/쓰기/원격 단계를 명확히; 광범위 새 설치기는 만들지 않음 |
| 스택 | `templates/stacks.json`, `scripts/stack-catalog.mjs`, `templates/stacks/` | 정본 중복 제약 정리; 지원 runner/실행 범위와 생성물 일치 |
| 작업 계약 | `plugins/harness-guard/skills/`, `codex/skills/`, `codex/native-runtime.md` | 공통 계약 정본·차이만 있는 wrapper; 읽기 경로를 실제 세션으로 확인 |
| 안내 라우팅 | `plugins/harness-guard/scripts/route-intent.mjs`, plugin hooks, 관련 fixture/문서 | 제거 전 reader·직접 소비·기존 출력 계약 조사; 가드 hook과 혼동 금지 |
| 전달 | `plugins/harness-guard/scripts/pr-*.sh`, required-check·policy 모듈, delivery skills | 현재 SHA/보호/복구 보존; branch 선택 원문 일치 |
| 문서 | README, 사용·온보딩·설치·제품 경계 문서 | 실제 독자별 한 경로, 역사 보존, 링크와 생성물 함께 이전 |
| 실험 | `experiments/split-packaging/`, 호환 shim | 기본 설치 경로와 분리 유지; 제거할 공개 alias는 이력·이전 안내 먼저 |

전 파일 이름 변경·새 디렉터리 구조의 미학 자체는 마일스톤이 아니다.
핵심 가드 재작성은 현재 필요성이 입증된 경계만 수행한다. 셸 모든 표현을 이해하는 보안 엔진으로 확장하지 않는다.

## 4. 필수 대표 반례

| 경계 | 입력·고장 | 기대 결과 |
|---|---|---|
| 첫 연결 | GitHub 없는 repo, 기존 충분한 검사, dirty 사용자 파일 | 필요한 점검 가능, 불필요 설치/remote 강제0, 사용자 파일 보존 |
| 스택 | pnpm lock이 있는 npm 선택, 빠진 필수 명령, 기존 checker | 준비/충돌 실패; 자동 runner 전환·가짜 성공 검사 생성0 |
| 적용 | preview 후 변경, 첫 파일 적용 뒤 타 writer 수정→다음 적용 실패 | 변경 감지 시 중단; 타 writer 변경 보존, 일치 파일만 복구, 부분 실패 보고 |
| 적용 중단 | 파일 사이 강제 종료, 소유 기록/원본 사본 부재 | 자동 복구 성공 주장0; 사본·현재 지문 대조의 수동 복구; 충돌/근거 부재 시 덮어쓰기0 |
| 진단 | 도구 자동 로그 생성·삭제, 제품 밖 알려진 캐시 경로 | 관찰한 쓰기 기준 위반 탐지; 관찰 밖 무변경 주장0 |
| 인계 | 낡은 PASS, 바뀐 요구, 살아 있는 다른 writer, 통합 검사 실패 | 최신 기준·소유 보존·부분과 전체 판정 분리 |
| 판정 | 다른 cwd/SHA, 원문 누락, 제외 파일의 쓰기, 추가 파일 | 해당 기준 FAIL/UNVERIFIED; 결과 집계가 누락을 숨기지 못함 |
| 브랜치 | main 중심 repo에 사용하지 않는 develop 존재 | 채택한 base 사용; 존재 기반 전환0 |
| 전달 | required check 누락/위조·조회 실패·검토 후 head 변경·복구 오류 | 병합 차단 또는 실제 부분 결과·복구 필요를 명확히 보고 |
| 설치 | 낡은 cache, 누락된 계약, 다른 plugin 설정, 업데이트 중 실패 | 실제 버전/경로 불일치 탐지; 다른 설정 보존과 복구 |
| 안내 | 생성만 성공·실행 안 함, 필수 실패·선택 미실행 | 연결/검증 완료를 구분; 필수 실패는 차단 |

표의 모든 행에 모델 실행이 필요한 것은 아니다. 결정적 경계는 CI에서, 의미·선택·인계는 실제 세션과 독립 검토로 확인한다.
시험 예산은 필요한 사례·예상 호출·중단 조건으로 구현 계획에 기록한다. 추가 반복으로 성공 표본을 고르지 않는다.
CLI 시간·토큰은 관측값이며 실제 요금·사람 생산성으로 환산하지 않는다.

## 5. 릴리즈·이전·복구

새 공개 인터페이스나 삭제가 확정되면 SemVer와 이전 안내를 함께 결정한다. 현재 미발행1.0.0을 자동 확정하지 않는다.
두 manifest·README·changelog는 실제 전달 후보와 맞춘다. 문서 설계만으로 버전을 올리지 않는다.
이 저장소는 작업 PR→원격 develop 병합 확인→그 결과에서 release/main PR→main 병합→태그→develop 역병합이다.
병합·태그·설치는 요청된 경우에만 진행하고 각 단계에서 현재 후보의 CI·리뷰·보호를 확인한다.
정식 release-check의 전체 품질·live external provenance·package/checksum 요구는 그대로 지킨다.

기존 제품의 생성 파일은 제품 소유다. 새 버전 설치가 이미 생성한 checker·AGENTS·CI를 자동 바꾸지 않는다.
호환 alias를 제거한다면 공개된 이전 경로와 실패 메시지·복구 절차를 제공한다. 조용한 동작 변경은 금지한다.
사용자 로컬 설치·전역 설정·원격 보호 변경은 정확한 대상과 승인 범위를 확인한다.
테스트용 임시 HOME·프로세스·의존성은 소유자를 확인해 정리하고 실제 정리 결과를 기록한다.

## 6. 완료 후 남길 것

- R1–R7의 현재 후보·지원 범위·실행·독립 판정 표.
- 최초 실패·원인·수정·영향 재시험과 미실행/보류의 원문 연결.
- 사용자에게는 변경 내용·사용 경로·이전 영향·정확한 완료 범위를 짧게 안내.
- 다음 제안은 현재 완료를 다시 여는 필수 항목으로 표시하지 않음.

M1–M5 구현과 고정 지원 범위의 검증을 완료했다. 기준별 결과·첫 실패·독립 판정은 [실행 기록](execution.md)을 따른다.
M6 릴리즈·영구 설치와 보편적 효용은 이 완료 판정에 포함하지 않는다. 임시 설치 시험은 v0.93.2 복구까지 마쳤다.
