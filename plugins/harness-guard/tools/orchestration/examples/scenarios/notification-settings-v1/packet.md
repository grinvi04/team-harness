# 합성 업무 패킷 — 업무 알림 설정 v1

2026-09-09 KST. **SYNTHETIC / 자료 준비 전용 / 실제 앱·역할 시험 NOT_RUN.**

이전 자료 준비 T1–T2의 합성 예시다. [이관 이력](../../../docs/history.md)을 참고한다. 실제 작성자는 주 작업 `/root` 한 명이다. 아래 역할명·예시 agent ID는 실제 역할 호출 기록이 아니며, 이 문서의 작성자 자체 점검은 독립 QC가 아니다. 운영 제품이나 회사 데이터에 적용하지 않는다.

## 1. 요구사항과 범위

가상 사용자 `fixture-user-1`이 화면 하나에서 업무 알림을 켜거나 끄고 저장한 뒤 다시 열어 같은 값을 확인한다. 사용자는 테스트 입력에 고정되며 로그인·권한 구현은 없다. 실제 알림 발송, 관리자·다중 사용자·동시 편집, 운영 DB/배포, 성능 비교는 제외한다. 저장 엔진·UI framework·HTTP 변환은 선택하거나 구현하지 않는다.

| 요구 ID | 요구 | 범위 AC | 전달 대상 |
| --- | --- | --- | --- |
| R-1 | 설정이 없는 정상 조회는 꺼짐. 저장된 `false`와 설정 부재를 구분하고 조회는 저장을 바꾸지 않음 | AC-1 | UX·데이터·BE·FE·QA |
| R-2 | 켜기 저장 → 다시 열기 켜짐 → 끄기 저장 → 다시 열기 꺼짐 | AC-1 | 데이터·BE·FE·QA |
| R-3 | 저장 전 실패 대역이 호출되면 기존 값/레코드 수 보존, 성공 표시 금지 | AC-2 | 데이터·BE·FE·QA |
| R-4 | `enabled`는 boolean만 허용. 같은 값을 두 번 저장해도 반전·레코드 중복 없음 | AC-3 | 데이터·BE·FE·QA |
| R-5 | 초기 조회·편집·저장·오류 상태 전달, 키보드 조작 가능, 저장 중 중복 요청 억제 | AC-4 | UX·FE·QA |
| R-6 | 필드/오류 의미 불일치, 오래된 ref, 증거 없는 성공·writer의 독립 판정은 수용하지 않음 | AC-5·6 | 조정자·QA·QC |
| R-7 | 요구 → 산출물 → 현재 후보 → 직접 증거 → 독립 판정 연결. 미실행을 통과로 표시하지 않음 | AC-7 | 모든 역할·조정자 |

이 문서는 원본 요구 R-1–R-7, UX 상태 U-1–U-7, 데이터/API 계약 D-1–D-3, 공개 검사 Q-1–Q-7을 한 버전으로 묶는다. 후속 소비자는 요약 대신 이 파일과 준비 보고의 SHA를 다시 읽는다. 의미가 바뀌면 조정자가 revision과 영향 소비자를 갱신해야 하며 현재 v1을 조용히 바꾸어 재사용하지 않는다.

## 2. UX 상태와 전달

화면에는 제목 “업무 알림”, 레이블이 연결된 체크박스 “업무 알림 받기”, “저장” 버튼, 상태 메시지 영역만 둔다. 키보드 Tab으로 항목/버튼에 접근하고 Space로 체크 상태, Enter/Space로 버튼을 조작한다. 포커스 표시를 유지하고 결과 메시지는 보조기기로 인지 가능해야 한다. 이는 명세이며 실제 접근성 검증이나 디자인 asset이 아니다.

| --- | --- | --- | --- |

## 3. 데이터와 API 계약

이 절의 API는 **논리적 입력/출력 계약**이다. 네트워크 endpoint·실행 함수·DB adapter는 아직 없다. 고정된 가상 사용자 외 식별자를 받는 인터페이스는 만들지 않는다.

### D-1 저장 불변조건

- 논리 레코드는 `(user_id, enabled)`이며 `user_id=fixture-user-1`에 최대 1개다. `enabled`는 null이 아닌 boolean이다.
- 레코드 없음의 조회 결과는 `false`지만 조회 자체는 기본 레코드를 생성하지 않는다. 이미 저장된 `false` 레코드를 없다고 취급하거나 삭제하지 않는다.
- 저장은 기존 값 반전이 아니라 요청 값으로 설정한다. 없는 경우 한 개 생성, 있는 경우 같은 레코드 갱신이다. 같은 요청 반복 후 레코드 수는 1이다.
- `SAVE_FAILED` 실패 대역은 값을 바꾸기 **전**에 거부한다. 실패 호출 기록, 이전 값/존재 여부/레코드 수와 이후 상태를 함께 관찰해야 한다. 실물 DB transaction·프로세스 재시작 내구성은 여기서 검증하지 않는다.

### D-2 조회/저장 입출력

| 경계 | 입력 | 정상 출력 | 거부·실패 출력과 효과 |
| --- | --- | --- | --- |
| 조회 | 없음; 사용자 고정 | `{"ok":true,"enabled":false}` 또는 `{"ok":true,"enabled":true}` | `{"ok":false,"error":"READ_FAILED"}`. 저장 변경 없음, U-6 |
| 저장 | 정확히 `{"enabled":true}` 또는 `{"enabled":false}` | 저장 완료 후 정상 조회와 같은 형식, `enabled`는 요청 값 | `{"ok":false,"error":"INVALID_INPUT"}` 또는 `{"ok":false,"error":"SAVE_FAILED"}`. 기존 상태 보존, U-7 |

입력 누락, 다른 필드명 `notificationsEnabled`, 추가 필드, `null`, `"false"`, `0`, 배열/객체를 boolean으로 강제 변환하지 않고 `INVALID_INPUT`으로 거부한다. 검증 실패 시 저장을 호출하지 않는다. 성공 응답의 `ok`와 `enabled`는 boolean이어야 하고, 실패 응답에는 성공 값을 섞지 않는다. FE가 알 수 없는 출력/필드/오류 코드를 받으면 U-6으로 처리하고 재조회 전에는 저장 성공을 표시하지 않는다.

### D-3 실패와 결과 불명의 구분

R-3은 **저장 전 거부가 확인되는 대역**을 시험한다. 응답 유실은 “저장되지 않았다”는 증거가 아니므로 U-6에서 재조회한다. 응답이 없는데 이전 값 보존을 단정하거나 자동 재시도하지 않는다. 이 경계 설명은 분산 장애·네트워크 복구 시험을 새로 승인한 것이 아니다.

## 4. 역할별 인수인계 지도

아래는 향후 담당 책임이며 이번에 그 역할들이 실행된 것이 아니다. 실제 배치는 주 조정자·디자인 담당·작은 FE/BE/데이터 묶음 구현 담당·독립 검증 담당 제안을 따른다. 동시 writer는 없다. 조정/공개 검사표 작성자와 구현자는 최종 QC를 맡지 않는다.

| 단계·책임 | 받는 원본 | 내보내는 산출물 | 다음 소비자의 거부 조건 |
| --- | --- | --- | --- |
| 기획·PM/조정·PL | 승인 범위·현재 요구 | R-1–R-7, 비목표, v1 ref·owner | UX·구현·QA: 요구/판정 방법 누락 또는 서로 다른 revision |
| UX/디자인 | R-1–R-5 | U-1–U-7, 키보드·메시지 명세 | FE·QA: 읽기 실패/저장 실패/결과 불명 상태 누락 |
| 데이터/DBA·BE | 요구·UX | D-1–D-3, 향후 저장/조회·거부 원시 증거 | FE·QA: 필드명·기본값·실패 의미 불일치 |
| FE | UX·고정 API ref | 향후 화면·조회/저장 소비 코드와 직접 관찰 | 통합 담당·QA: 화면만 성공이고 저장 값이 다름 |
| QA | 요구·UX·API | Q-1–Q-7과 C-1–C-5, 실패 주입이 실제 작동하는지 검사 | 구현자·QC: 기대 출력만 있고 실패 호출/원본 비교가 없음 |
| 통합/PL | 각 제출물·현재 기준·writer 이력 | 향후 통합 후보 ref/diff와 인수인계 기록 | 독립 QC: 충돌·누락·오래된 산출물이 포함됨 |
| 독립 QC | 고정 요구, 통합 후보/diff, 모든 writer 이력·원시 증거 | 향후 AC별 판정, 근거와 잔여 위험 | 조정자·사용자: writer가 판정, ref 불일치, 미실행을 PASS로 보고 |

이 패킷의 정적 자료 위치는 채워져 있지만, **실제 후보·실제 증거·독립 판정은 모두 NOT_RUN**이다. 이것을 AC-7의 실제 증거 빈 칸 0으로 세지 않는다. 계약 변경은 조정자가 소비자에게 다시 전달하고, 구현자/검증자가 몰래 공개 기준을 약화하지 않는다.

## 6. 반례 카드 5개

이는 공개 반례의 **입력 설명과 예상 판정**이다. 실제 앱에 결함을 주입했거나 독립 검증자가 검출한 결과가 아니다.

| 카드 | 합성 입력·실패 방식 | 예상 판정 | 필요한 직접 증거·기존 검사의 한계 |
| --- | --- | --- | --- |
| C-1 계약 불일치 | 저장 소비자가 `enabled` 대신 `notificationsEnabled`를 전달하거나 그 필드만 있는 응답을 받음 | 실제 거부/형식 오류 표시가 없으면 AC-5 FAIL. 증거 없으면 INCONCLUSIVE | 실제 FE 경계 payload·응답·상태, D-2 현재 원본. Envelope JSON에는 업무 payload가 없으므로 assignment-only가 유효여도 검출한 것이 아님 |
| C-2 저장 실패 은폐 | 기존 false, true 저장에 SAVE_FAILED를 반환했는데 UI는 “저장했습니다.” | AC-2·5 FAIL. 대역 미호출/저장 관찰 없으면 INCONCLUSIVE | 실패 대역 호출·이전/이후 저장 값·UI. 보고에 명시 FAIL 근거가 있으면 이를 보존. 앱을 실행하지 않은 이번 자료에는 FAIL 실행 증거를 꾸며 넣지 않음 |
| C-3 옛 ref 혼입 | 현재 Task/Assignment는 v1인데 Artifact의 `task_revision`만 `synthetic-task-v0` | 기존 비교가 `task-mismatch`로 거부. 현재 원본도 대조한 뒤 소비 거부 | 세 JSON의 정확한 입력·검사 오류, 현재 원본 ref. 옛 결과를 새 revision으로 이름만 바꾸어 수용하지 않음 |
| C-4 세 입력 모두 옛 ref | Task/Assignment/Artifact의 task revision과 요구/공개 검사 ref를 모두 일관된 v0으로 바꾸고 최근 observed_at만 붙임 | 비교기는 유효할 수 있음. 현재 원본 v1과 다르면 소비 거부; 원본 접근 불가면 BLOCKED/INCONCLUSIVE | 조정자가 따로 읽은 현재 원본. 최근 시각·세 입력의 일치가 최신성 증거가 아님. 이번 메모리 v0/v1 비교는 실제 원본 조회 시험이 아님 |
| C-5 writer의 독립 판정 위장 | 현재 소유권은 없지만 검증자의 instance가 과거 candidate_writers에 있음 | 기존 비교가 `verifier-was-writer`로 거부. 이력을 숨기면 정적 비교만으로 보장 못 함 | 실제 source/config/요구/test/oracle writer 이력·실제 agent binding. rename이나 소유권 반환으로 이력을 삭제하지 않음 |

## 7. JSON 3개와 읽는 방법

[task.json](task.json), [assignment.json](assignment.json), [artifact.json](artifact.json)은 **구현 책임의 API·데이터 계약 제출 → 조정자/QC 소비**라는 한 전달 경계의 합성 예시다. 전체 역할별 실제 Task 세트가 아니다. Task의 `SYN-H1`은 이 경계의 문서 전달 기준이며 R-1–R-7/AC-1–AC-7 전체 업무 통과를 대신하지 않는다.

- 모든 ref·instance/agent ID·시간은 합성이다. `urn:synthetic:notification:packet`과 `synthetic-packet-v1`은 이 파일의 설명용 별칭이지 조회 가능한 원본이나 content hash가 아니다. 실제 파일 지문은 준비 보고에 따로 남긴다.
- `state=RUNNING`, `mode=write`는 관계 검사 입력일 뿐 실제 실행 상태/권한이 아니다. `allowed_tools=[]`, 쓰기 경로 없음, 실제 호출 금지다. 소유 target도 `synthetic:`으로 시작하는 가상 결정 ID다.
- `wall_clock_seconds=1`은 양수를 요구하는 schema의 합성 수치이며 새 실행 예산 승인이 아니다. 실제 역할 실행 0회, 주 대화 사용량은 별도다. Artifact의 예시 소비 시간 0/비용 null도 주 대화 사용량을 뜻하지 않는다.
- Artifact는 `complete=false`, `verdict=INCONCLUSIVE`, 실행 evidence 빈 배열이다. 형식 유효성을 보이려고 미실행 명령·역할·권한·PASS 증거를 만들지 않는다.
- 여러 기능을 맡는 합성 구현 인스턴스는 binding 하나를 공유한다. 공개 기준 작성자·디자이너·구현자의 합성 writer 이력을 유지하고 별도 합성 verifier와 구분한다. 실제 자료 작성자는 여전히 `/root` 한 명뿐이다.

저장소 루트에서 다음 **자료 검사 명령만** 사용한다. 입력의 명령이나 ref를 실행/조회하는 도구가 아니다.

```sh
node scripts/validate-assignment.mjs examples/scenarios/notification-settings-v1/task.json examples/scenarios/notification-settings-v1/assignment.json examples/scenarios/notification-settings-v1/artifact.json
```

exit 0은 assignment-only다. 기존 `npm run check`는 루트 예시를 검사하므로 이 패킷은 위 명령으로 별도 검사한다. 실제 앱·역할·권한 시험은 승인 범위의 실행 선행 조건을 충족하기 전까지 BLOCKED이며, 자료 준비 후 자동으로 실행하지 않는다.

이번 자료의 실제 검사 결과와 파일 지문은 [준비 보고](../../../docs/history.md)에 남긴다. 합성 Artifact의 evidence와 섞지 않는다.
