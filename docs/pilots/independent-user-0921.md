# 0.93.0 후보 독립 사용자 인수 양식

정본 기준은 [독립 팀 인수 계약](../company-acceptance.md#독립-팀의-업무-인수)이다.
이 자료는 그 계약의 실행·기록 양식이며 새 인수 기준이나 실행 권한을 만들지 않는다.
사용자가 실제 개발자·리뷰어가 있다고 확인했다. 역할·대상·업무는 아직 미지정이다.
현재 상태는 **로컬 양식 준비 / 실제 수행 UNVERIFIED**다. 회사 인수 전체 완료가 아니다.
2026-10-13 사용자 요청으로 실제 인수를 발행·설치 전에 수행한다. 이 양식은 인수 3의 준비 자료다.
저장소·참여자·업무가 정해져야 실행한다. 이미 완료한 Harness 로컬 개선은 반복하지 않는다.
현재 실행 범위는 [원래 요구·현재 코드 대조](../company-acceptance.md#원래-요구와-현재-harness-판정)다.

## 시작 전에 고정할 내용

아래 미정 값이 있으면 해당 제품의 변경·검사·원격 PR을 시작하지 않는다.
참여자가 이 자료를 읽고 실제 업무와 허용 명령을 정한다. 작성자 설명은 따로 기록한다.

| 항목 | 현재 값 / 작성할 내용 |
|---|---|
| 대상 | 미정: 저장소·기준 브랜치·40자리 시작 SHA·기존 변경의 보존 방법 |
| 업무 | 미정: 실제 이슈·요구·설계/진단/변경/유지보수 범위와 비목표 |
| 개발자 | 존재 확인 / 별칭·Harness 작성자와의 관계·도구 숙련도 미정 |
| 리뷰어·인계 수신자 | 존재 확인 / 별칭·독립성·승인/CODEOWNER 자격 미정 |
| 허용 환경 | 미정: 비운영 경로·명령·합성 데이터·정리 대상·예산 |
| 제품 수용 기준 | 미정: 정상·실패·경계 흐름의 기대 결과와 원래 필수 검사 |
| 기준선 | 미정: 같은 요구·시작 SHA·검사 범위의 native+CI 실행 기록 |
| 효용 판단 | 미정: 채택/보류를 판단할 시간·누락 방지·인계의 기대 이득 |
| 원격 행동 | 미승인: 제품 PR·CI·병합·초대·권한 부여는 대상 확정 후 별도 범위 확인 |

기준선은 발행 v0.92.1/source SHA `4e0d66b9fa34d273bb1ee7383846601d3fa2fd99`다.
검증한 로컬 소스 후보는 0.93.0/`c6f519770d2740d1dc36971799dae7e126bc57cc`이며 미발행이다.
실행 전에 사용할 후보 SHA·자산 plan을 고정한다. 미커밋 자료나 로컬 버전 배지를 발행 태그로 취급하지 않는다.
기존 회사 보호·hook·AGENTS·검사·lockfile을 보존하며 회사 경로의 solo 예외는 0이다.
DriveTree 수정·운영·기존 DB/Auth/Storage·원본 환경 파일·원격 보호 변경은 제외한다.
참여자가 있다는 답변은 연락·초대·계정/설정 변경의 승인이 아니다.

5. 제품의 기존 지침·요구·검사 명령: Harness 표준보다 해당 제품의 기준을 먼저 확인.

## 실제 업무의 수행 순서

대표 업무 한 건을 고른다. 기능 추가만으로 한정하지 않으며 관계없는 전 업무를 억지로 수행하지 않는다.
한 사례의 통과는 그 업무·환경의 결과다. 설계·진단·릴리즈 등 미관찰 영역까지 확대하지 않는다.

| 단계 | 수행자·행동 | 남길 원본 |
|---|---|---|
| 1. 기준선 | 개발자: 기존 native+CI 방식, 같은 요구·시작 후보·필수 검사 | 명령·후보·실행/대기 시간·재작업·리뷰 지적 |
| 2. 선택·적용 | 개발자: 안내만으로 최소 자산을 선택하고 preview 후 허용된 사본에 적용 | plan·source SHA·전후 diff·소유 기록·hook/정책 보존 |
| 3. 실제 업무 | 개발자: 요구 확인·설계 또는 진단·승인된 변경·제품 검증 | 결정 이유·변경 SHA·실패/재시도·기대 결과별 명령/exit/로그 |
| 4. 리뷰·인계 | 독립 리뷰어: 요구·현재 diff·실행 원문 대조, 수신자가 다음 행동 설명 | 지적·판정·PR/CI·후보/위험/다음 행동의 발견 결과 |
| 5. 충돌·유지 | 개발자: 폐기 사본에서 관리 파일 충돌·갱신/제거를 관찰 | 거부 exit·원본 보존·해결 선택·재검사·제거 전후 diff |
| 6. 비용·판정 | 두 참여자: 기준선과 단계별 비용을 대조하고 채택/보류 이유 결정 | 아래 관찰표·작성자 개입·한계·서명 또는 원본 리뷰 링크 |

정상 업무를 두 번 수행하면 학습·순서 효과가 생긴다. 각 경로는 같은 시작 후보의 분리 사본을 쓰고
도구·환경·순서·기존 경험을 기록한다. 기준선이 없으면 임의로 추정하지 않고 비용 비교 UNVERIFIED다.
다른 업무/후보의 과거 시간을 동일 조건의 기준선으로 취급하지 않는다. 한 사례로 ROI를 단정하지 않는다.
기존 기준선이 있다면 원문·동일 요구/환경을 대조해 재사용하고 형식적인 재실행을 요구하지 않는다.

## 적용 명령의 선택

명령의 정본·옵션은 [자산 안내](../repo-assets.md)다. 대상과 허용 경로를 채운 뒤 사용한다.
`SOURCE`는 시험 SHA의 깨끗한 checkout, `TARGET`은 승인된 별도 Git 사본의 절대 루트,
`PLAN`은 참여자가 검토한 JSON 파일이다. 이 자료는 경로를 대신 선택하거나 적용하지 않는다.
`SOURCE_REVISION`은 그 checkout의 전체 40자리 SHA다. 실행 기록에 값을 그대로 남긴다.
기존 AGENTS/hook을 덮어쓰는 plan을 만들지 않는다. 기술 자산만 선택해도 된다.

```bash
node "$SOURCE/scripts/manage-repo-assets.mjs" apply \
  --repo "$TARGET" --source "$SOURCE" \
  --revision "$SOURCE_REVISION" \
  --plan "$PLAN"
```

위 명령은 미발행 SHA의 preview이며 소유 기록은 `unreleased:<SHA>`다. 0.93.0 태그를 먼저 만들지 않는다.
발행된 기준선에는 동일 SHA의 `--version v0.92.1`을 붙일 수 있다. 태그 없는 후보에 붙이면 거부된다.
경로·diff를 검토한 동일 명령에만 `--apply`를 붙인다. 사전 제품 인수와 발행·전역 설치 인수는 구분한다.
실제 적용 후 `bash "$SOURCE/scripts/harness-doctor.sh" --repo "$TARGET" --components tech`로
관리 자산을 진단하고 제품의 기존 명령을 별도로 실행한다. doctor PASS를 앱 검사 성공으로 세지 않는다.
구성과 제품 동작에 연결되지 않은 파일 복사는 실제 채택의 완료 증거가 아니다.

충돌 시험은 폐기 사본에서 관리 파일 하나를 변경한 뒤 remove preview가 exit2로 거부하며
변경 파일을 보존하는지 확인한다. 정상 remove와 update도 먼저 preview하고 승인된 사본만 변경한다.
update에는 실제로 다른 고정 원본이 필요하다. 0.92.1에서 미발행 후보로 갱신할 때도 SHA와 실제 diff를 기록한다.
없는 태그나 같은 원본의 no-op을 갱신 인수로 세지 않는다. 기준선과 후보는 별도 깨끗한 checkout을 사용한다.
새 원본이 없으면 갱신 항목은 UNVERIFIED로 남긴다. 시험용 수정 Harness를 발행 원본으로 위장하지 않는다.

## 관찰 기록 양식

제품의 기존 기록 위치에 아래 표를 복사한다. 새 상태 엔진이나 전역 메모리를 만들지 않는다.
시간은 실제 측정한 분 단위 값, 미측정은 UNVERIFIED로 쓴다. 대기와 실제 작업 시간을 나눈다.

| 단계 | 기존 방식 작업/대기 분 | Harness 작업/대기 분 | 재작업·도움 요청 | 원본·한계 |
|---|---|---|---|---|
| 준비·적용 | UNVERIFIED | UNVERIFIED | UNVERIFIED | 미실행 |
| 요구·설계/진단·변경 | UNVERIFIED | UNVERIFIED | UNVERIFIED | 미실행 |
| 검증·리뷰·인계 | UNVERIFIED | UNVERIFIED | UNVERIFIED | 미실행 |
| 갱신·제거 | UNVERIFIED | UNVERIFIED | UNVERIFIED | 미실행 |

| 필수 관찰 | 기대 결과 | 실제 원본·판정 |
|---|---|---|
| 정책·기존 자산 | 약화0·회사 solo0·무단 덮어쓰기0 | UNVERIFIED |
| 필수 검사 | 누락/실패/미확인의 완료 처리0, 실제 후보와 증거 일치 | UNVERIFIED |
| 인계 | 수신자가 원본·후보·위험·다음 행동을 스스로 발견 | UNVERIFIED |
| 독립성 | 도구 작성자의 코칭 없이 실행, 개입이 있으면 횟수/내용 기록 | UNVERIFIED |
| 수명주기 | 적용·충돌 해결·실제 갱신·제거와 기존 파일 보존 | UNVERIFIED |
| 효용 | 실측 비용과 안전성/인계 이득을 참여자가 설명하고 채택 판단 | UNVERIFIED |

필수 FAIL/UNVERIFIED가 있으면 인수 3 완료는 아니다. 코칭 후 성공은 보조 실행 결과로 구분한다.
접근 불가·참여자 미실행·갱신 버전 부재는 SKIP이 아니다. 실제 업무에 해당하지 않는 영역만 사유로 제외한다.
원격 PR/CI/승인은 별도 허용 범위에서만 실행하고 사람 승인·현재 head의 결과를 AI 리뷰로 대신하지 않는다.
부작용이나 기존 정책 충돌을 발견하면 해당 동작을 중단하고 증거와 필요한 선택을 보고한다.

## 이번 준비 단계의 종료 기준

자료·읽기 경로·출처 SHA·형식과 기존 인수 계약의 일관성을 확인한다.
제품 적용·사용자 수행·비용 비교·원격 실행은 대상과 원본 결과 없이는 완료로 기록하지 않는다.
실제 인수 1 FAIL, 2/3 UNVERIFIED는 유지한다. 문서의 로컬 작성·검증과 PR·발행은 구분한다.
