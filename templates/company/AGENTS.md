# 회사 프로젝트의 선택형 개발 계약

이 안내는 기존 회사 지침에 추가할 초안이다. 기존 AGENTS·CLAUDE·관리 정책을 덮어쓰지 않는다.
채택할 항목과 원본 버전은 제품 저장소의 검토 기록에 연결한다.

## 프로젝트가 먼저 정할 항목

- 기본 브랜치와 PR 대상은 회사 Git 정책을 따른다. main-only도 가능하다.
- 언어·commit validator·format·lint·테스트 명령은 제품의 기존 정본을 사용한다.
  Team Harness의 한국어 commit validator·develop 흐름·전체 템플릿은 선택 사항이다.
- 요구·계획·승인은 기존 이슈·설계 문서·PR 등 회사가 사용하는 기록에 연결한다.
  파일 존재는 승인 증거가 아니다. 이미 승인된 작업의 계획·승인을 반복하지 않는다.
- 공유 stack rule을 채택했다면 해당 원문 경로를 기록하고 작업 전에 읽는다.
  앱의 lockfile·배포·DB·Auth·Storage 변경 권한은 별도로 확인한다.

## 개발과 검증

변경 전 요구, 직접 소비자, 관련 검사와 현재 문서를 확인한다.
작업과 정상·거부·경계 검사를 짝짓고 기존 사용자 파일·검사를 보존한다.
의미 변경은 제품의 실제 검사 명령으로 확인한다. fixture 통과는 제품 실행 증거가 아니다.
실행하지 않은 필수 검사는 미확인이며 완료로 세지 않는다.
관련 현재 안내·체크리스트·인계 기록을 실제 후보와 함께 갱신한다.

## GitHub 구성을 채택한 경우

수동·자동 병합 모두 현재 head의 비어 있지 않은 required 집합 성공을 확인한다.
승인·CODEOWNERS·기존 보호는 회사 정책을 보존한다. 리뷰어 부재는 승인 우회 이유가 아니다.
회사 경로에서는 solo 보호 예외를 사용하지 않는다. 자동머지는 명시 승인한 대상만 사용한다.
로컬 설정·파일 존재·과거 CI 성공을 서버 집행이나 새 후보의 성공으로 간주하지 않는다.

## 도구와 인계

기존 hook과 관리 설정을 유지한다. 새 자산 연결은 검토한 별도 파일로 시작한다.
기술 자산만 쓰는 프로젝트에는 Codex·GitHub 설치를 요구하지 않는다.
AI는 구현·검증·병합·릴리즈·설치·배포·회사 인수를 구분해 보고한다.
독립 리뷰어가 요구·현재 후보·증거를 직접 대조할 수 있는 인계 자료를 남긴다.
