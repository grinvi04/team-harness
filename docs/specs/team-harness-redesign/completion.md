# 재설계: 완료와 검증의 계약

상태: 사용자 승인된 검증 계약. [전체 설계](../team-harness-redesign.md)의 R2–R7을 구체화한다.
기존 QA 원칙을 더 길게 복사하는 대신, 어디서 어떤 사실을 수집하고 무엇을 판정할지 정한다.

## 1. 작업 기준의 정본

기존 스펙·이슈·PR 중 해당 업무의 현재 정본 하나를 사용한다. 새 task 서버·필수 JSON·상태 엔진은 없다.
작은 작업은 아래 정보가 있는 짧은 목록으로 충분하다. 다른 형식으로 같은 정보를 복제하지 않는다.

| 필드 | 의미 | 예 |
|---|---|---|
| 기준 ID·요구 출처 | 원래 요청과 연결 | B1: 설정 변경 후 현재 조회 결과 |
| 허용 범위·보존 대상 | 무엇을 바꾸고 무엇을 유지하는가 | 해당 함수·새 회귀, 기존 사용자 변경 보존 |
| 기대 결과·관찰 경계 | 무엇을 직접 보면 충족인가 | 공개 조회 값·파일 변화·제품 루트 검사 |
| 필수 여부·제외 근거 | 완료를 막는 조건과 해당하지 않는 영역 | 필수 루트 검사, 배포는 요청 밖 |
| 후보·근거·판정 | 어느 상태를 실제 확인했는가 | 커밋/작업트리·명령·원문·PASS/FAIL/UNVERIFIED |

기준이 원래 목적을 대표하는지는 독립 검토가 확인한다. 형식 검사가 이를 보증하지 않는다.
사용자의 자연어 정정이 최우선이다. 같은 목표를 명확하게 표현하는 정정과 목표·권한 변경을 구분한다.
실패를 통과시키기 위한 기준 삭제·필수→선택 변경은 금지한다.

## 2. 실행 사실과 의미 판정

실행 사실은 도구·CI·관찰기에서 읽는다. 에이전트가 쓴 PASS 문구를 실행 사실로 복사하지 않는다.

| 구분 | 기록할 것 | 하지 못하는 주장 |
|---|---|---|
| 후보 | repo·HEAD, dirty/untracked 대상의 내용 지문·명시 제외, 관련 환경·계약 지문 | HEAD만으로 미커밋 후보 전체 동일성 |
| 명령 | 실제 argv/명령·cwd·시도·exit·원문 위치·지문 | 명령 이름이 같으므로 다른 폴더의 성공 전용 |
| 변경 | 사전/사후 관찰 집합·추가/삭제/수정·소유자·제외 | 관찰하지 않은 파일시스템 전체의 무변경 |
| 외부 상태 | 조회 대상·시각·응답·출처·현재 SHA | 응답 오류를 검사 없음이나 성공으로 해석 |
| 의미 | 기대값 근거·독립 검토·반례·한계 | 테스트 수·체크섬으로 전체 요구 충족 자동 확정 |

관찰 범위에 포함된 ignored 파일·로그·캐시도 비교한다. 제외 목록과 수정 금지 기준이 겹치면 PASS를 내지 않는다.
Git diff만으로 ignored/untracked 변화 전체를 확인했다고 하지 않는다. 알려진 도구 쓰기 경로를 시험 설계에 포함한다.
OS·플랫폼이 자체 기록하는 영역을 관찰하지 못하면 그 영역까지 무변경이라고 표현하지 않는다.
비밀·개인정보는 수집하지 않는다. 실행 기록은 필요한 비민감 사실만 보존하고 임시 인증 사본은 종료 시 제거한다.

## 3. 동일한 기준으로 끝내기

| 상태 | 뜻 | 종료 판단 |
|---|---|---|
| PASS | 현재 범위·후보에서 기대 결과를 확인 | 해당 기준 충족 |
| FAIL | 실행 실패 또는 기대값 반례 | 필수면 미완료 |
| UNVERIFIED | 미실행·원문 부족·관찰 누락·다른 후보 | 필수면 미완료 |
| SKIP | 실제 비적용이며 근거 있음 | 실패·인증 오류·시간 부족의 대체값으로 사용 금지 |

요청한 범위의 필수 기준 PASS, 미해결 차단 결함 0, 필요한 독립 검토와 기록 일치가 완료 조건이다.
기능·검증·통합·병합·발행·설치는 각자 증거를 가진다. 선택하지 않은 단계를 현재 잔여 개수에 넣지 않는다.
업무에 “부분 결과를 정확히 인계”가 포함되면 전체 제품 실패를 보존한 인계도 해당 기준은 PASS일 수 있다.
최종 답변은 전체 정본에서 현재 결과를 요약한다. 지도·보고서마다 독립 완료 플래그를 수동으로 만들지 않는다.

## 4. 완료 이후 새 발견

새 발견은 반드시 기존 기준 ID 또는 새로운 범위에 연결한다.

| 발견 | 처리 |
|---|---|
| 기존 필수 기준을 실제 반증 | 영향받는 판정을 정정하고 후보·원인·회귀와 필요한 재시험을 연결 |
| 기존 기준의 필수 증거 누락 | 해당 항목을 UNVERIFIED로 정정하고 필요한 증거만 수집 |
| 계획 때 명시한 제외/한계 | 기존 완료를 유지. 새로운 요청 없이 필수 작업으로 재편입하지 않음 |
| 새로운 편의·확장·추가 효과 제안 | 별도 제안. 현재 종료를 막지 않음 |
| 분류할 증거 부족 | 사실 확인을 먼저 하고 기존 실패나 완료로 단정하지 않음 |

새 반례가 나올 수 있다는 사실과 현재 완료 기준이 흔들리는 것은 다르다.
기준을 고정한다고 발견된 결함을 무시하지 않으며, 가능한 모든 우려를 필수 기준으로 늘리지도 않는다.

## 5. Harness 자체 평가를 제품으로 관리

최근 `.runtime/` 관찰기의 필요한 책임을 `tests/acceptance/`로 이전했다.
기존 `tests/fixtures/qa-command-binding.mjs`와 회귀를 대조했으며 실제 검출력은 [M1 기록](execution.md)에 연결한다.
이는 Harness 저장소의 평가 도구이며 소비 프로젝트에 설치하는 범용 완료 CLI가 아니다.
입력은 고정 시험 기준·fixture 후보·실제 도구 원문·관찰 지문이고, 출력은 기준별 결과 한 벌이다.
Markdown 보고는 그 결과와 독립 의미 검토를 참조한다. 사람이 별도의 전체 PASS 값을 여러 곳에 입력하지 않는다.

구현 책임은 세 개면 충분하다.

1. **관찰:** 실제 파일 집합·추가/삭제/수정·명령 시도와 exit 수집. controller와 actor의 쓰기를 구분.
2. **기계 판정:** 누락·후보 불일치·관찰/주장 충돌·필수 실패 집계. 제출한 값의 의미는 판정하지 않음.
3. **독립 검토:** 원래 요구·잠긴 기대값·실행 원문·최종 설명의 적합성을 반증. 결과를 수정하지 않고 판단 제공.

관찰기·판정기의 다음 반례는 모델 없이 CI에서 실행한다.

| 입력 | 기대 결과 |
|---|---|
| 허용 밖 캐시 파일 생성·기존 로그 삭제 | 각각 범위 FAIL; 정상 무변경은 PASS |
| 관찰 제외 경로를 포함해 변경 0 주장 | UNVERIFIED 또는 잘못된 시험 계약 오류 |
| 기대 파일은 같지만 새 파일이 하나 추가 | 정확 집합 비교 실패 |
| 다른 cwd·다른 SHA·dirty 내용 변경·계약 digest 변경 | 해당 증거 무효; 변경과 무관한 증거의 재사용은 근거 필요 |
| 원문 없는 PASS·누락된 필수 명령·다른 시도 exit 전용 | UNVERIFIED/모순 오류 |
| 첫 실패 후 성공, 원인·변경 설명 없음 | 필수 불안정 결과를 소급 PASS 처리하지 않음 |
| FAIL 항목을 집계에서 누락하거나 중복 ID 사용 | 보고 생성 실패 |
| secret가 포함된 원문·외부 경로를 따라가는 링크 | 수집 거부/안전한 제거 후 재수집; 원문 외부 전송 금지 |

체크섬 핀만 갱신한 것을 행동 회귀 시험이라고 하지 않는다.
로컬 실행 원문 전체를 공개할 필요는 없지만, 공개 결과를 재현할 명령·fixture·비민감 지문·판정기는 저장소에 남긴다.

## 6. 지원 경로의 시험

소스·artifact·공식 loader·실제 세션을 연결하는 지원 경로를 검사한다.
[지원·인수 집합](architecture.md#이번-재설계의-지원인수-집합)의 필수 실행 행을 고정 범위로 사용한다.
Claude는 소스 호환 회귀만 포함하며 실호스트 보류를 해제하지 않는다. 다른 호스트의 성공으로 필수 행을 채우지 않는다.
실제 세션 시험에서는 계약 본문을 프롬프트에 대신 공급하지 않고, 공개 안내에 있는 진입 방식으로 시작한다.
명시 skill 호출과 자연어 자동 선택은 별도 결과다. 후자의 표본 성공을 모든 요청의 자동 선택 보장으로 확대하지 않는다.
자동 선택 실패 시 명시 호출 경로로 복구할 수 있어야 하며 그 실패도 보존한다.

필수 표본은 단순 횟수 대신 책임 경계를 대표한다.

- 로컬 전용 기존 repo: 기존 검사 재사용·미지원 runner·승인 전 쓰기 거부.
- 진단→수정: 실제 시작 경로·범위·원래 결함 RED→GREEN·제품 필수 검사.
- 새 문맥 인계: 최신 요구·살아 있는 writer·부분/전체 실패 구분.
- GitHub 전달: 채택한 branch·필수 검사 누락·후보 이동·보호 복구. 실제 원격은 승인된 시험 대상에서만 수행.
- 설치/갱신/복구: 실제 배포물 지문·공식 loader·다른 설정 보존·실패 후 복구.

기존 증거는 관련 후보·환경·관찰 경계가 같으면 재사용한다. 최종 릴리즈 gate의 신선도 요구는 별도 적용한다.
Claude 실제 호스트 보류, 실제 회사·사람 참여, 소비 제품 고유 기능 검증은 현재 승인 없이 재개하지 않는다.

## 7. 효용과 제품 신뢰의 차이

안전한 연결·거부·정확 보고는 동작 계약이다. 빠른 개발·더 좋은 설계·비용 감소는 별도 효과 주장이다.
후자는 같은 요구·환경의 비교와 시간·문맥·재작업 관측이 있어야 한다. 현재 세 흐름은 인과적 개선을 입증하지 못했다.
효과가 없거나 비용만 늘린 새 안내·라우팅·문맥 계층은 제거/축소 후보로 다룬다.
전체 기능의 통계적 우위를 증명할 때까지 무한 시험하지 않는다. 실제 검증한 효과만 제품 설명에 쓴다.
