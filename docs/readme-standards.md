# README 표준 — 프로젝트 repo README 양식

[표준 적용 기준](standards-scope.md)을 따른다. README는 처음 온 사람이 목적·현재 상태·시작 방법을 찾는 문서다.
제품의 종류·독자·언어에 맞춰 구성한다. 모든 repo에 앱 기능·계정·배포 섹션을 강제하지 않는다.

## 1. 섹션 순서

권장 순서다. 해당 없는 항목은 생략하고 중요한 정보는 앞에 둔다.

| 항목 | 남길 내용 |
|---|---|
| 소개 | 무엇을 해결하는지, 대상 독자 |
| 현재 상태 | 지원 범위·버전·검증·알려진 제한 |
| 시작하기 | 실제 준비 조건과 최소 실행 경로 |
| 검사 | 실제 lint·test·build 명령과 제외 범위 |
| 구조 | 이해에 필요한 연결·책임·디렉터리 |
| 참고 | 작업 규약·공식 문서·상세 사용 안내 |
| 라이선스 | 실제 라이선스와 사용 조건 |

웹 앱이면 접속·로그인 경로, 라이브러리면 설치·호출 예시, CLI면 명령과 입력·출력을 우선한다.
실제 기능이 없는 검색·차트·계정·배포 단계를 예시 때문에 추가하지 않는다.

## 2. 스타일 규칙

- 독자가 사용하는 언어로 쓴다. 전문 용어는 필요한 곳에서 짧게 설명한다.
- 한 문장에 한 가지 정보를 담는다. 명령은 준비 조건·대상·기대 결과와 함께 쓴다.
- 배지는 현재 확인한 상태를 표시한다. 과거 테스트 수를 현재 후보의 통과로 표현하지 않는다.
- 구현·검증·머지·발행·설치·배포 완료를 구분한다.
- 상세 사용법은 정본으로 연결한다. 여러 문서에서 같은 설명을 별도로 유지하지 않는다.

## 3. Do / Don't

지원하지 않는 단계와 미확인은 명시한다. 비밀정보나 실제 운영 계정은 README에 넣지 않는다.
시험 계정 안내가 필요하면 승인된 비운영 계정의 발급·사용 경로만 설명한다.
출처 없이 기술을 업계 표준이라고 쓰거나, 구조 검사 통과를 제품 품질 보장으로 표현하지 않는다.

## 4. 아키텍처 다이어그램 — mermaid + 이미지 폴백

다이어그램이 이해를 돕는 경우에만 추가한다. Mermaid·SVG·정적 이미지 중 독자의 뷰어에 맞는 방식을 선택한다.
Mermaid는 GitHub와 지원 확장·뷰어에서 렌더된다. IDE 전체에서 불가능한 것은 아니다.
[Mermaid 지원 목록](https://mermaid.js.org/ecosystem/integrations-community.html)에서 현재 뷰어를 확인한다.
렌더되지 않는 환경도 지원해야 하면 이미지나 짧은 텍스트 설명을 함께 제공한다.
이미지를 제공하면 원본 소스·재생성 경로를 연결하고 변경 시 둘을 같은 작업에서 맞춘다.
커스텀 SVG가 필요하면 [선택형 SVG 안내](architecture-diagram-standards.md)를 따른다.
특정 이미지 크기·색·형식을 모든 제품의 정본으로 강제하지 않는다.

## 5. 적용

새 repo는 `templates/README.template.md`에서 필요한 부분만 채운다.
기존 README는 독자와 실제 사용 경로를 보존하고 이번 변경에 필요한 부분만 수정한다.
