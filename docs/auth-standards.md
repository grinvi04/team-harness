# 인증·인가 표준

[표준 적용 기준](standards-scope.md)을 따른다. 인증은 사용자를 확인하고, 인가는 허용된 행동과 데이터를 판단한다.
특정 공급자나 업무 권한 모델을 모든 프로젝트에 강제하지 않는다.

## 인증

- 기존 인증 체계와 제품의 로그인 요구부터 확인한다. 관리형·셀프호스트 공급자는 프로젝트에서 선택한다.
- OIDC/OAuth를 사용하면 흐름·토큰 종류·지원 클라이언트를 정한다. 일반 사용법은 공식 자료를 따른다.
  Authorization Code 로그인에는 PKCE와 S256을 적용한다. 요청과 응답의 연결, redirect URI,
  OIDC의 nonce 검증도 확인한다. Implicit·비밀번호 직접 전달 흐름을 새 기본값으로 선택하지 않는다.
- 토큰을 받는 서버는 서명, 허용 알고리즘, 발급자, 대상 서비스, 유효 시간을 검증한다.
  ID 토큰과 access 토큰을 혼동하지 않는다. 허용된 키·발급자 설정은 비신뢰 입력으로 바꾸지 않는다.
- 만료·폐기·로그아웃·갱신 실패 시 동작을 정의한다. 세션 수명은 위험과 사용 방식으로 정한다.
- MFA와 계정 복구는 선택한 공급자의 기능과 제품의 위험에 맞춰 적용한다.

브라우저의 토큰 저장 방식은 위협과 사용 환경을 함께 검토한다.
민감한 인증 토큰을 localStorage에 저장하지 않는다. BFF는 서버가 토큰을 보관하는 선택지다.
쿠키 세션을 쓰면 HttpOnly·Secure·SameSite와 CSRF 방어, 세션 폐기를 함께 설계한다.
쿠키 속성이나 PKCE 하나만으로 전체 인증 흐름이 안전하다고 판단하지 않는다.

공식 기준: [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html),
[OAuth 보안 권고](https://www.rfc-editor.org/rfc/rfc9700.html),
[OWASP 세션 관리](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
Keycloak을 선택한 프로젝트는 [Keycloak 안내](https://www.keycloak.org/documentation)를 따른다.
Keycloak·AWS 사용은 이 공통 표준의 전제가 아니다.

## 인가

- 모든 보호 대상 요청에서 서버가 최종 권한을 검사한다. UI의 버튼 숨김은 보안 경계가 아니다.
- 기본값은 거부다. 기능 권한과 객체·조직·사용자별 데이터 범위를 함께 검사한다.
- 역할 기반(RBAC)·속성 기반(ABAC) 등 모델과 권한 이름은 제품에서 정한다.
- 목록뿐 아니라 단건 조회, 수정, 삭제, 일괄 처리, export, 배치·외부 연동에도 범위를 적용한다.
- ORM 필터는 직접 SQL·다른 DB 접근 경로까지 자동 보호하지 않는다. 우회 경로를 확인한다.
- 다른 사용자·다른 조직의 식별자, 낮은 권한, 만료된 세션으로 실패·거부 사례를 검증한다.
- 권한 변경 이력과 서비스 계정의 권한·수명을 관리한다. 업무 승인 규칙은 제품 문서에 둔다.

[OWASP 인가 안내](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)는
매 요청 검사와 기본 거부를 설명한다. 문서 채택만으로 소비 앱의 집행이 검증되지는 않는다.

## 보안 공통 규칙

- 입력은 경계에서 길이·형식·범위를 검증한다. 업무 불변식도 서버에서 검사한다.
- 개인정보의 수집·마스킹·보존·파기는 해당 제품의 요구로 정한다. 로그에 불필요하게 남기지 않는다.
- 비밀정보는 코드·공개 설정·로그에 넣지 않는다. 배포 환경의 보호된 저장소로 주입한다.
- 로컬 비밀 파일은 추적·출력·외부 전송하지 않는다. 특정 클라우드의 저장소를 필수로 두지 않는다.
- secret-scan과 보안 리뷰의 검사 범위를 확인한다. 통과를 전체 보안 보장으로 보고하지 않는다.
- 유출은 [시크릿 대응](operations-secret-response.md)에 따라 처리한다. 운영 조치에는 기존 권한이 필요하다.
