# plan — 프로젝트 계획 연결

일반 설계·계획은 선택한 Superpowers의 brainstorming/writing-plans 또는 native 방법론 하나를 따른다.
먼저 [공통 프로젝트 계약](../ao-coordinate/project-contract.md)을 읽고 기존 산출물에 연결한다.
이미 승인된 계획을 다시 작성하거나 같은 승인 절차를 반복하지 않는다.

## 계획에 남길 내용

제품의 기존 기록 하나에 목표·이유, 포함/비목표, 보존 대상과 현재 승인 범위를 남긴다.
정상·실패·경계의 수용 기준, 영향 파일·직접 소비자, 기준별 검사와 기대 결과를 연결한다.
필요한 만큼의 태스크·의존성과 미결정 사항을 기록하며 문서 길이·질문 횟수를 목표로 삼지 않는다.

새 `feature/<name>` 브랜치가 필요하면 `docs/specs/<name>.md`에 승인 범위와 정본 링크를 둔다.
계획만 요청받으면 계획 산출물까지만 작성하며 코드·브랜치·커밋·PR을 변경하지 않는다.
구현까지 승인됐다면 기존 계획에서 신규 동작은 feature-add, 변경은 feature-modify 계약으로 이어간다.
