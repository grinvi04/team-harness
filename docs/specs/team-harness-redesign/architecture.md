# 재설계: 구조와 실제 사용 경로

상태: 사용자 승인된 재설계 계약. 실제 구현·검증 상태는 [실행 기록](execution.md)을 따른다.

## 1. 경계와 의존

| 책임 | 입력 | 결과 | 소유하지 않는 것 |
|---|---|---|---|
| 프로젝트 연결 | 현재 repo·앱 경로·기존 검사·선택한 자산 | 읽기 전용 진단, 적용 diff, 소유 자산 기록·복구 | 앱 코드·DB 설계·모든 도구 설치 |
| 작업 계약 | 현재 요청·규약·기존 작업·수용 기준 | 계획/변경/검토/인계의 현재 기록 | 모델 선택·스케줄러·권한 엔진 |
| 검증 | 해당 기준·후보·원문 실행·변경 관측 | 기준별 결과·제외·불확실성·독립 판단 | 업무 의미의 자동 증명·무결함 보장 |
| GitHub 전달 | 채택한 브랜치 흐름·승인 범위·현재 PR/보호 | PR/병합/태그/복구의 실제 결과 | 로컬 작업의 원격 강제·회사 정책 창작 |

실행 플랫폼은 native adapter를 통해 계약·가드에 연결된다. adapter는 플랫폼별 입력을 정규화하며 정책을 복제하지 않는다.
프로젝트 연결과 로컬 검증은 GitHub·plugin·split package 설치에 의존하지 않는다.
전달은 검증 결과를 소비하지만 자체 GitHub 원본을 다시 조회한다. 로컬 PASS가 서버 gate를 대체하지 않는다.
작업 기록은 제품 저장소의 기존 스펙·이슈·PR에 있다. Harness에 두 번째 task database를 만들지 않는다.

## 2. 사용자에게 보이는 흐름

시작은 제품 디렉터리에서 실제 업무를 말하는 것이다. 준비가 충분하면 설치·셋업을 반복하지 않는다.

| 상황 | 동작 | 완료 기준 |
|---|---|---|
| 기존 repo 첫 사용 | 규약·dirty 파일·검사·브랜치 방식·사용 가능한 도구 확인 | 현재 상태와 부족한 연결을 설명; 허용하지 않은 쓰기 없음 |
| 기존 검사가 충분 | 그대로 업무 시작 | 새 checker·설정 파일을 만들지 않아도 정상 지원 |
| 검사 연결 부족 | 스택별 준비 조건 확인→preview→선택 적용 | 원래 제품 검사를 보존하고 선택한 파일만 추가 |
| 빈 디렉터리 | 앱 준비가 선행임을 설명하고 실제 개발 방식으로 연결 | 앱 준비와 Harness 연결의 결과를 구분 |
| 설계·진단·리뷰 | 해당 산출물과 근거까지 수행 | 원인/설계 발견을 구현·PR 권한으로 확대하지 않음 |
| 승인된 수정 | 유지 조건·정상·결함 검사 연결 후 좁게 변경 | 현재 후보의 변경·검사·독립 검토와 기준 일치 |
| 중단·인계 | 최신 요청·소유자·후보·실패·다음 행동 확인 | 다른 작업을 침범하지 않고 재개 가능한 범위만 이어감 |
| PR·릴리즈 요청 | 채택한 흐름과 기존 보호를 조회하여 wrapper 실행 | 현재 후보·CI·리뷰·원격 결과·복구를 단계별 확인 |

작은 팀도 같은 흐름을 쓴다. 담당 파일·의존 관계·통합 책임·리뷰 주체만 기존 기록에 추가한다.
설계·보안 진단·성능 개선·의존성 갱신·장애 대응도 같은 목표/범위/근거 구조에 각 업무의 검사를 연결한다.
실제 운영 접근·DB/Auth/Storage·배포 권한은 이 구조만으로 생기지 않는다.

## 3. 프로젝트 연결

현재 `scripts/setup-local.mjs`, `scripts/manage-repo-assets.mjs`, `scripts/new-repo.sh`의 책임을 분리한다.
새 단일 facade CLI를 우선 만들지 않는다. 기존 명령의 입출력·부작용을 일관되게 정리한다.

- **점검:** GitHub 없이도 로컬 규약·앱·검사를 읽는다. manifest script는 데이터로 읽고 점검 과정에서 실행하지 않는다.
- **미리보기:** 생성·갱신·충돌·삭제 예정 파일, 목적과 소유권을 제시한다. 네트워크·제품 실행·파일 쓰기는 없다.
- **적용:** 명시한 계획과 현재 파일이 같고 대상 파일의 배타적 편집이 확보된 경우 수행한다. 부분 실패는 아래 복구 경계를 따른다.
- **갱신·제거:** Harness가 소유한 자산과 사용자 수정 여부를 대조한다. 기록이 없거나 drift가 있으면 임의 삭제하지 않는다.
- **원격 정책:** 자산 연결과 별도 단계다. 조회 실패면 쓰지 않고, 기존 보호 완화는 기본 적용에 포함하지 않는다.

기존 검사 진입점이 제품 통합 시험을 포함하면 공통 checker로 대체하지 않는다.
직접 연결 또는 별도 호출 순서를 표시하고, 생성 성공과 검사 실행 성공을 다른 결과로 보고한다.
사용자가 수정하는 소스·AGENTS·lockfile·.env·workflow는 자동 정리 대상이 아니다.

적용·갱신·제거 동안 같은 파일을 다른 writer가 편집하지 않는 것이 전제다. Harness 실행 간 충돌은 잠금으로
거부하되 이 잠금이 편집기·다른 도구까지 막는다고 하지 않는다. 배타성을 확보할 수 없으면 격리 사본에 적용해 diff만 인계한다.
각 쓰기 직전과 복구 직전에 현재 내용·모드를 대조한다. 복구는 Harness가 방금 쓴 상태와 일치하는 파일만 대상으로 한다.
불일치 파일은 보존하고 전체 복구 성공 대신 부분 실패·충돌 경로를 보고한다. 임의 외부 writer와의 경합 안전성은 보장하지 않는다.
여러 파일 적용 전체를 원자적이라고 부르지 않는다. 강제 종료의 자동 복구는 이번 지원에서 제외한다.
쓰기 전에 선택한 비민감 자산의 원본 사본·계획·소유 지문을 승인된 위치에 보존하고, 중단 뒤 현재 파일과 대조하여
일치 항목만 수동 복구하는 절차를 제공한다. 원본 사본이 없거나 사용자 변경과 충돌하면 덮어쓰지 않는다.

## 4. 스택은 검사 프로필

정본은 기존 `templates/stacks.json`과 스택 원문을 사용한다. key/order/role의 중복 하드코딩을 정리한다.
프로필에는 앱 경로·스택·실행기·버전 조건·필수 명령·선택 명령·네트워크/쓰기 요구를 표현한다.
필수 여부는 제품 계약이 우선하며, 카탈로그의 기본값이 제품 필수 통합검사를 선택 검사로 내릴 수 없다.

| 범위 | 유지하는 현재 상태 | 새 설계에서의 표시 |
|---|---|---|
| 로컬 검사 | Spring Boot/Gradle와 Vue·Node·React/Vite·Next.js·Nuxt/npm | 실제 지원 runner·lock·명령·검증 환경 명시 |
| CI 템플릿 | 현재 8스택과 지원 조합 | 템플릿 제공과 실앱 실행 증거를 다른 열로 표시 |
| Python/Rails 로컬, Maven/pnpm 등 | 현재 로컬 생성기 미지원 | 자동 대체하지 않고 기존 제품 명령 사용 가능 여부 안내 |
| 여러 앱 | 각 앱의 경로·독립 프로필 | 고정 Spring+Vue 로컬 쌍을 복원하지 않음 |

정본과 생성된 CI/로컬 파일을 구분하고 생성 drift를 검사한다.
스택 확장은 실제 제품 요구·명령·정상/거부 시험이 있는 경우에만 추가한다.

## 5. 작업 계약과 native adapter

설계/진단/변경/검증/인계의 공통 핵심은 한 원문에 둔다. 개별 skill은 차이와 필요한 참조만 연결한다.
자동 선택은 플랫폼의 제안 기능이다. 발견됨·본문 읽힘·실제 준수·권한 집행을 같은 상태로 부르지 않는다.
`route-intent`의 기본 UserPromptSubmit 연결은 제거했다. legacy 소스·시험과 권한·가드·PR wrapper는 보존한다.
기존 skill 이름을 없애는 경우 먼저 안내와 동등 진입을 제공한다. 모든 workflow를 새 만능 skill로 합치지 않는다.

공개 배포는 한 plugin으로 유지한다. core·adapter·계약의 내부 책임은 분리하지만 독립 설치를 강제하지 않는다.
공식 loader와 실제 지원 surface에 맞추고 자체 cache patch·의존 resolver·agent TOML·권한 설치를 만들지 않는다.
기존 설치·업데이트·rollback 구현을 재사용하며, 다른 plugin·개인 설정 보존을 필수로 검사한다.
Codex와 Claude는 어댑터 단위로 상태를 기록한다. Claude 실제 호스트 보류는 해제하지 않는다.
미확인인 host/version에 대해 “전체 지원 검증 완료”라고 표시하지 않는다.

### 이번 재설계의 지원·인수 집합

R6와 M5는 다음 표의 **필수 실행** 행만 실제 호스트 완료 조건으로 삼는다. 호환 유지 행은 소스·패키지 회귀만 필수다.
이 표는 승인된 인수 범위다. 실제 시험 후보·버전·결과는 [실행 기록](execution.md)의 R6에 연결한다.
아래 메타데이터와 실제 동작 증거를 구분하며 표 밖 환경으로 결과를 확대하지 않는다.

| 호스트·surface | 기준 환경 | 인수 분류 | 허용할 제품 설명 |
|---|---|---|---|
| Codex CLI의 공식 plugin loader·명시 skill·도구 hook | macOS arm64, CLI 0.161.0 | 필수 실행: 격리 설치→본문 로딩→허용/거부 도구 실행 | 통과한 후보·버전에서 이 경로 확인 |
| 현재 데스크톱의 Codex 실행 surface·skill·도구 hook | macOS arm64, 현재 호스트 앱26.1007.30912(20156), 내장 CodexCLI build1 | 필수 실행: 실제 새 세션의 경로·본문·hook 관측 | 확인한 호스트 세션에 한정; CLI 결과로 대체 금지 |
| Codex의 자연어 skill 자동 선택 | 위 두 환경 | 선택 동작 관측; 실패 시 명시 진입 복구는 필수 | 자동 선택 항상 성공 주장 금지 |
| Claude Code adapter·skill·hook | 기존 소스/배포 형식 유지; 실호스트 버전 미확인 | 호환 소스 유지·실행 미확인 보류 | 소스 회귀와 실제 실행 상태를 따로 표시 |
| 다른 OS·버전·별도 데스크톱 배포판·다른 실행 플랫폼 | 현재 고정된 필수 집합 밖 | 제외; 기존 증거는 당시 범위로 보존 | 새 후보 검증 완료 주장 금지 |

현재 실행 경로는 `ChatGPT.app` 안의 `CodexCLI.app`에서 확인했다. 별도 `Codex.app`의 검증 결과로 바꾸어 부르지 않는다.
실행 전에 바이너리·앱·plugin 후보 지문을 고정한다. 자동 업데이트 시 같은 surface의 변경 영향과 실제 시험 버전을 기록하며,
미지원 경로 추가나 필수 행 제외로 통과 조건을 바꾸지 않는다. 필수 경로 실행이 불가능하면 해당 행은 UNVERIFIED다.

## 6. GitHub 전달

대상 branch는 **명시 입력 → 제품이 채택한 선언**으로 정한다. 둘이 충돌하면 실행 전에 해소한다.
추정만 가능한 상황에서는 예정 base를 제시하며, 옛 develop 존재만으로 흐름을 결정하지 않는다.
팀/solo는 소유권·현재 정책·사용자 선택으로 정하며 개인 계정이라는 이유로 승인 요구를 없애지 않는다.
이 저장소의 Git Flow는 유지한다. develop과 main PR을 선행 병합 확인 없이 동시에 생성하지 않는다.

현재 후보 고정·required checks 출처·리뷰·보호 복구는 재사용할 핵심이다.
전송/조회 코드와 판정 함수를 분리해 응답 오류·페이지 누락·후보 이동을 독립 시험할 수 있게 한다.
부분 실패는 실제로 끝난 원격 행동과 실패한 후속 행동을 보고하고, 근거 없이 반복 실행하지 않는다.
로컬 hook은 조기 방어다. 서버 정책은 GitHub가 집행한다. 어떤 계층도 임의 셸·권한 전체를 보증하지 않는다.

## 7. 문서와 소스 배치

| 현재 자산 | 설계 후 책임 |
|---|---|
| README | 제품 약속·한 시작 경로·실제 지원 범위·세부 안내 링크 |
| development-coordination + team guide + developer-workflow | 하나의 사용 정본과 필요한 팀/전달 참조; 같은 절차 중복 제거 |
| company-onboarding + local-development + repo-assets | 기존 프로젝트 연결의 공통 경로, 로컬/원격/소유 자산별 세부 참조 |
| harness-setup + plugin/native 문서 | 설치·점검·실제 host 검증·갱신·복구의 정본 |
| product-direction + product-boundaries | 제품 약속과 실제 책임. 미발행 실험을 현재 설치 기능처럼 보이지 않게 함 |
| tests의 기존 회귀 + 새 acceptance 하위 영역 | 정책 회귀와 실제 사용자 경로 평가. 실행 원문·판정기 반례 포함 |
| experiments/split-packaging | 비기본 실험·역사로 유지. 공개 경로의 실행 의존으로 승격하지 않음 |

현재 파일명을 한 번에 옮기는 일이 목표가 아니다. 정본·reader·직접 소비자를 함께 이전하고 옛 링크를 연결한다.
각 Markdown은 199줄 이하로 유지한다. 핵심 권한·완료 조건을 링크 뒤에만 숨기지 않는다.
진행 지도는 현재 정본을 보여주는 보기이며, 별도 완료 판정의 원본이 아니다.

## 8. 첫 사용 예시
