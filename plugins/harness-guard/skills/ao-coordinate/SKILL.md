# 개발 작업의 인계와 재개

제품 저장소의 현재 지침·요구사항과 진행 기록을 연결해 승인된 작업을 이어간다.
현재 단계의 Harness workflow 하나를 사용하고, 이 skill을 별도 계획·승인·구현 절차로 중첩하지 않는다.
별도 npm 패키지, JSON 계약, 역할 설치나 상태 서버는 필요 없다.

## 시작·재개

- 제품의 실제 루트, AGENTS.md, 요구사항 원본과 현재 Git 변경을 확인한다. 제품별 기술 선택을 따른다.
- 기존 이슈·PR·스펙에서 완료 조건, 미완료 항목, 다음 행동을 찾는다. 같은 상태를 새 문서에 복제하지 않는다.
- 기록이 없고 여러 단계의 인계에 필요할 때만 제품의 기존 문서 관례에 맞게 짧게 기록한다.
  채팅 요약이나 과거 시험의 다음 작업을 현재 계획으로 취급하지 않는다.
- 요구·후보·담당 범위가 달라졌다면 영향을 받는 증거와 작업만 다시 확인한다.
  이미 유효한 검증과 승인된 범위를 이유 없이 다시 시작하거나 재승인받지 않는다.

## 필요할 때만 나누기

단순 작업은 현재 에이전트가 처리한다. 독립 작업이나 필수 독립 검토가 있고 실제 플랫폼과 제품 지침이
허용할 때만 위임한다. 직무별로 고정 인원을 만들지 않는다. 실행·권한·중단은 현재 플랫폼 도구를 사용한다.

위임 입력에는 아래 내용 중 해당 작업에 필요한 것을 전달한다. 별도 형식 파일을 만들 필요는 없다.

- 목표·비목표와 원래 수용 기준, 현재 원본 경로·후보
- 담당 변경 경로와 다른 작업자의 변경, 공유 인터페이스·의존성
- 허용 행동과 금지 행동, 필요한 검증, 예산·중단 조건

담당자의 실제 응답·도구 상태를 확인한다. 사용할 수 없는 역할·권한·예산 계측값을 만들어 적지 않는다.
동시 writer는 제품과 플랫폼이 허용하는 격리·소유권 조건을 충족해야 한다. 같은 파일과 공유 자원은 직렬 처리한다.
읽기 전용 역할 지시는 기술적 접근 제한의 증거가 아니다. 작업에 기술적 제한이 필수이면 실제 적용을 확인하고,
불가능하면 해당 작업을 차단한다. 모든 일반 작업에 과거 실험의 권한 gate를 새로 부과하지 않는다.

## 결과를 인계하고 검사하기

결과에는 변경 범위, 실제 후보(commit과 미커밋 변경 포함), 실행한 검사와 결과, 미해결 사항, 다음 행동을 남긴다.
결과를 받은 쪽은 현재 후보와 원래 수용 기준에 대조한다. 형식이 맞거나 작성자가 완료라고 했다는 이유만으로 인수하지 않는다.

제품 정책이나 위험에 따라 독립 검증이 필요한 경우 구현자와 다른 인스턴스에 원래 요구사항·현재 후보·검증 방법을 전달한다.
검증자는 후보를 수정하지 않는다. 결함 수정은 구현자에게 돌리고 변경의 영향을 받는 검사를 다시 수행한다.
필수 검증을 실행할 수 없으면 미확인으로 남긴다. 자기 검사를 독립 검증으로 바꾸어 부르지 않는다.

## 중단·완료

중단된 작업은 실제 역할·프로세스의 실행 상태부터 확인한다. 조용하다는 이유만으로 종료를 추정하지 않는다.
기존 writer의 정지와 남은 변경을 확인하기 전에는 같은 범위를 재할당하지 않는다. 권한 거부를 다른 도구나 역할로 우회하지 않는다.
새 근거 없이 같은 실패를 반복하지 않는다. 차단된 항목과 필요한 판단을 기록하고 독립적으로 가능한 승인 작업은 이어간다.

현재 후보의 수용 기준과 제품의 필수 검사·리뷰·승인 결과를 확인한 뒤 해당 범위의 완료를 보고한다.
실패·미확인·차단을 통과로 처리하지 않는다. 로컬 구현, PR 병합, 릴리즈의 완료를 구분하고 권한을 확대하지 않는다.

인계가 필요하면 기존 제품 기록에 다음 정도만 남긴다. 이미 같은 정보가 있으면 링크한다.

| 필요한 정보 | 기록할 내용 |
| --- | --- |
| 요구·현재 후보 | 요구사항 위치, branch/commit과 남은 변경 |
| 완료 조건·진행 | 기준별 완료·진행·차단 상태, 담당 범위 |
| 검증 근거 | 검사 방법·결과·대상 후보, 누락·남은 위험 |
| 다음 행동 | 이어갈 단계, 실행 중 작업, 필요한 판단 |

단순 수정에는 이 표나 새 문서를 강제하지 않는다. 제품 상태는 제품 저장소와 GitHub가 소유한다.
