# 클린 아키텍처 적용 표준

[표준 적용 기준](standards-scope.md)을 따른다. 복잡한 업무 규칙과 외부 기술의 변경을 분리할 때 선택한다.
모든 프로젝트에 동일한 디렉터리나 계층 수를 강제하지 않는다.

## 1. 구조 (Java/Spring 기준)

계층을 채택한 모듈의 예시다. 이름과 모듈 경계는 제품에서 정한다.

```text
module/
  domain/       # 업무 규칙
  application/  # 유스케이스와 외부 경계의 인터페이스
  adapter/      # HTTP·DB·외부 서비스 연결
  api/          # 다른 모듈에 공개하는 계약
```

의존 방향은 `adapter → application → domain`이다. 업무 규칙이 외부 구현에 직접 의존하지 않게 한다.
모듈 경계를 채택하면 공개 계약을 정하고 내부 구현의 직접 참조를 줄인다.
공통 코드는 실제 여러 호출부가 필요할 때만 둔다. 제품의 업무 규칙을 공통 패키지로 옮기지 않는다.

## 2. 실용적 절충 (순수주의 배제)

도메인 모델과 ORM 모델을 분리할지, 같은 모델을 사용할지는 비용과 변경 위험으로 정한다.
JPA 어노테이션 허용 여부도 해당 프로젝트의 결정이다. 템플릿과 검사에서 같은 정책을 사용한다.
단순 CRUD나 Rails·Django의 기본 구조에 의미 없는 계층을 추가하지 않는다.
CQRS·이벤트 소싱은 현재 문제와 운영 비용을 확인한 뒤 별도로 결정한다.

## 3. 경계 강제 수단 (규율은 도구로)

| 경계 | 선택할 수 있는 수단 | 확인할 것 |
|---|---|---|
| 모듈 의존 | 빌드 모듈, 공개 API 분리, Java Module System | 금지 참조가 실제 실패하는가 |
| 내부 계층 | ArchUnit, dependency-cruiser 등 | 프로젝트 검사와 CI에 연결됐는가 |
| 데이터 소유권 | 접근 권한, 쿼리 검사, 통합 테스트 | 직접 SQL·조인·배치도 검사하는가 |

Gradle 서브프로젝트만으로 공개 클래스의 내부 패키지 접근까지 막지는 않는다.
패키지 접근 제한은 [Gradle의 Java 모듈 안내](https://docs.gradle.org/current/userguide/java_library_plugin.html#sec:java_library_modular)에 따라 별도로 구성한다.
[ArchUnit](https://www.archunit.org/userguide/html/000_Index.html) 같은 도구는 선택·설치·규칙 연결 후에만 강제 수단이 된다.
현재 Harness는 모든 소비 repo에 아키텍처 테스트를 설치하거나 모든 크로스 스키마 조인을 차단하지 않는다.
규칙 위반 예제가 실패하고 정상 예제가 통과하는지 확인한다. 설정 파일 존재만으로 강제를 보고하지 않는다.

## 4. TDD 결합 — 계층이 곧 테스트 전략

업무 규칙은 빠른 단위 테스트로, DB·직렬화·권한 경계는 실제 기술을 사용하는 검사로 확인한다.
필요한 계층만 시험한다. mock의 정상 응답을 전체 데이터 정합성의 증거로 사용하지 않는다.
[QA 계약](ai-collaboration.md#qa-범위와-완료-기준)에 요구·실패 영향·검사 결과를 연결한다.

## 5. 모듈 → 미니서비스 분리 시점의 작업

독립 배포·성능·소유권의 필요가 있을 때 분리를 검토한다. 모듈이 나뉘었다고 분산 시스템 전환이 단순하지는 않다.
데이터 이관, 트랜잭션, 실패·재시도, 중복 메시지, 순서, 계약 버전과 관측성을 별도로 검증한다.
DB 저장과 메시지 발행의 불일치에는 [Transactional Outbox](https://microservices.io/patterns/data/transactional-outbox.html)를 검토할 수 있다.
추가 저장·전달 작업과 중복 소비 처리가 필요하므로 모든 프로젝트에 필수로 도입하지 않는다.

## 6. 스택별 변형

Spring·NestJS는 선택한 계층 경계를 검사에 연결한다.
Rails·Django는 프레임워크 기본 구조를 활용하고 복잡해진 부분만 분리한다.
세부 문제 해결은 [백엔드 안내](stack-troubleshooting-backend.md)를 따른다.
