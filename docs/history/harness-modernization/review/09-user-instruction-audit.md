# 사용자 지시 대조 — 발견 목록과 원래 요구의 구분

확인일: 2026-10-09 KST. 대상은 현재 전역 설정·Team Harness·네 소비 문서의 재검토와 계속 유효한 운영 조건이다.
원본 코드·설정·프로젝트 문서는 수정하지 않았다. 이 대조와 계획 보완은 임시 검토 폴더에만 저장했다.

## 직전 검증에서 부족했던 점

앞서 확인한 57개는 보고서의 발견 ID다. 이를 계획에 모두 연결했다는 사실은 사용자 지시를 모두 충족했다는 증명이 아니다.
직전 검증은 발견→담당 단계 연결을 확인했고, 원래 지시→증거/계획→현재 이행 상태를 별도로 대조하지 않았다.
이번에는 실제 사용자 요청과 선택 답변을 기준으로 아래 표를 만들었다. 단순한 ID/키워드 존재를 의미 충족으로 취급하지 않는다.

두 부분을 보강했다: 원래 지시의 추적 표, Git 추적 여부에 기대지 않는 사용자 관리 MD의 대상 기준.
SNS·모델 비교·실제 host 실행의 미확인은 이미 보고됐지만, 특히 SNS 보충 조사를 명시적인 실행 항목으로도 연결했다.

새 지시나 원본 변화가 생기면 해당 행과 영향 단계를 다시 대조한다.

## MD 대상의 빈틈 보완

계획의 기존 표현은 tracked 문서 + 지정 전역/지도 문서였다. 현재 지도 6개는 이미 범위에 포함됐지만,
향후 사용자 관리 문서가 미추적/ignored 상태라는 이유로 빠지는 것을 막는 명시적인 소유 기준이 약했다.
새 기준은 tracked + 미추적 사용자 관리 MD + 명시적으로 소유한 ignored 지침/스펙/진행 문서다.
외부 plugin 원본·cache·dependency·backup을 이 기준으로 편집 대상에 넣지 않는다.

[이번 대상 재대조](../instruction-audit-md-boundary.json)는 다섯 repo의 tracked MD 253개와
Harness 지도 2개·소비 지도 4개의 경로를 확인했다. 지정 경로에서 새 누락 후보는 발견하지 못했다.
이는 모든 ignored 디렉터리를 전수 조사했다는 뜻이 아니다. 구현 시작 시 소유 문서/생성 MD 목록을 고정하고 변경 후보에서 검사한다.
전역 지정 7개와 개인 project-map skill도 기존 범위대로 유지한다.

## SNS 요구의 현재 한계와 보충

로그인 없이 최신 모델명·X 도메인·날짜/effort 조건을 바꾼 공개 검색을 수행했다.
이번 결과에서도 관련 최신 X 직접 원문을 확보하지 못했다. 검색 결과 부재를 게시글 부재로 일반화하지 않는다.
2013년의 관계없는 X 블로그 결과는 제외했다. 새 계정/로그인/유료 도구·접근 우회는 사용하지 않았다.

2026-09-30의 [사용량/품질에 긍정적인 Sol 후기](https://www.reddit.com/r/codex/comments/1wtq7vg/gpt61_sol_is_very_good_for_the_plus_users/)와
[속도/사용량에 비판적인 후기](https://www.reddit.com/r/codex/comments/1wuatzt/gpt61_sol_feels_unlimited_because_it_runs_at_20/)는 직접 열어 보충했다.
두 글은 사용자 체험이며 동일 환경의 통제 비교가 아니다. 주장 수치·구독 한도·공급자 의도를 확인된 사실로 채택하지 않는다.
이 표본은 모델 품질·재작업·총시간·실제 사용량을 함께 측정해야 한다는 가설에 연결한다.

[검색 범위·제외·보충 근거](../instruction-audit-sns-evidence.json)를 남겼다.
최신 X 사례 요구는 부분 이행으로 유지하며, 공개 원문이 새로 확보되면 모델/effort·날짜·과제·결과·측정 한계로 대조한다.
SNS 접근 부족으로 공식 지원이나 실제 품질 비교를 대체하지 않는다. 같은 검색 실패를 근거 없이 반복하지 않는다.

## 과거 요청과 현재 승인

과거 샘플/앱 수정·파일 삭제·릴리즈·특정 PR 보호 예외는 해당 시점의 원본 기록과 승인 범위를 따른다.
이번 표는 그 모든 과거 작업의 실행 완료를 다시 증명하는 문서가 아니며, 새 앱 기능/배포/보호 예외 권한을 만들지 않는다.
현재 조사는 샘플 시험의 기존 증거와 안전한 fixture를 재사용한다. 삭제 요청한 샘플을 임의로 재생성하지 않는다.
이번 계획을 구현할 때 필요한 새 후보/host/reader 검증은 agent가 수행하고, 불가능하면 사유와 해제 조건을 남긴다.
