## 요구와 범위

사용자는 혼자 백엔드·프론트엔드·DB·인프라 업무를 수행하면서 검증된 설정·검사 방법을 재사용하고,
실제 프로젝트에서 도움이 된 구성을 차츰 다른 개발자에게 확산하려 한다. 회사 공통 기준의 선행 확정이나
모든 제품의 GitHub 공개는 요구가 아니다. 선택 통합 완료를 이 목표의 완료로 표현하지 않는다.

이번 변경은 **연결**이다. 기존 기술 기준·native 위임·완료 절차를 이 사용 흐름에 연결한다.
새 실행 엔진·모델 역할 설치·사용량 할당제·회사 정책·애플리케이션 생성기는 만들지 않는다.
전역 모델 설정·설치된 플러그인 cache·샘플 앱과 데이터를 수정하지 않으며 샘플 원격 저장소를 만들지 않는다.
Team Harness 변경은 기존 PR·CI·머지 절차를 따른다. 이 소스 변경만으로 전역 설치 적용을 주장하지 않는다.

## 수용 기준

- [x] README·제품 방향·온보딩·개발 안내가 개인 사용 → 검증된 구성 재사용 → 점진적 확산 순서를 설명한다.
  로컬 사용과 GitHub 도입을 구분하고, 아직 없는 범용 시작 자동화를 완료로 쓰지 않는다.
- [x] 작업 시작·인계·완료 절차가 관련 로드맵·체크리스트·진행 문서의 현행화를 요구한다.
  현재 상태와 과거 증거를 구분하며, 기존 기록을 갱신하고 별도 상태 체계를 만들지 않는다.
- [x] Codex는 요구·소유 파일·검사 기준이 명확한 저위험 구현을 승인된 native worker에 맡길 수 있다.
  구현자와 검증자, 테스트 계약과 구현, Git 통합 책임을 분리한다. 필수 권한·리뷰·CI gate는 유지한다.
- [x] 모델 선택은 사용자 설정을 존중한다. Luna/max와 같은 승인된 역할을 배제하지 않지만 사용량 목표를
  만들지 않는다. 주간 실제 실행 집계와 설정·계정 사용량의 차이, 확인 불가 항목을 구분한다.
- [x] 직접 소비 문서·wrapper·템플릿·manifest를 함께 갱신하고 기존 품질 검사와 독립 내용 검토를 통과한다.

## 검증 방법

이 변경은 실행 스크립트가 아닌 지침·제품 범위 수정이다. 문구를 그대로 단언하는 새 테스트 대신 기존
Codex wrapper·배포 경계·제품 방향·템플릿 검사를 실행하고, 독립 검토자가 수용 기준·실제 diff·호출 계약을
대조한다. 주간 모델 조사는 로컬 metadata만 읽으며 추가 모델 비교 실험이나 API 비용 환산을 하지 않는다.
패키지 검사는 커밋된 후보를 사용한다. 로컬 검증·PR 병합·릴리즈·전역 설치를 별도 상태로 보고한다.


## 확인 결과와 다음 행동

- 2026-09-22: 기존 quality 59단계를 실행하고 실패 원인 수정 후 해당 검사를 통과했다.
  임시 검사 도구는 저장소 밖으로 이동했고 생성 CHANGELOG와 의도적으로 변경한 공용 지침 3개의 해시 기준을 갱신했다.
  소개 버전의 고정값 검사는 실제 manifest 대조로 바꿨다. 기존 가드·권한·CI 판정은 완화하지 않았다.
- 독립 검토에서 발견한 현재 로드맵·모델 안내·완료 체크리스트·배포 및 관측 범위 모순을 수정하고 재검토를 통과했다.
  추가한 로컬 문서 참조의 파일·앵커도 확인했다. 이 검증은 모든 미래 작업의 문서 누락 방지를 자동 보장하지 않는다.
- 모델 점검은 설정과 호스트의 최근 168시간 실행 metadata를 분리했다. 개인 집계 수치는 저장소에 게시하지 않는다.
  이 변경은 배정 계약 보완이며 실제 Luna/max 활용 비중 개선이나 비용·품질 우위를 입증한 비교 시험이 아니다.
- 0.71.0 릴리즈 후보의 quality 59단계·독립 보안 검토·필수 CI 5개를 통과했다.
  승인된 호스트의 설치 갱신과 새 loader의 스킬 17개 활성화·로딩 오류 0개를 확인했다.
  모델·역할과 다른 plugin은 보존했다. 이는 해당 호스트의 로딩 확인이며 runtime 권한 집행 증거는 아니다.
- 후속 구현은 [첫 재사용 시작 구성 #462](https://github.com/grinvi04/team-harness/issues/462)와
  [현재 명세](local-spring-vue-setup.md)에서 관리한다.
  릴리즈·설치와 전체 제품 목표는 이 명세의 구현 완료와 구분한다.
