## 보존된 정적 화면 제안과 정보의 뜻

1. 상단은 선택 작업명·상태·전체 담당·기다리는 이유·다음 행동으로 압축했다. 질문 카드5개를 제거했다.
2. 중앙 ‘함께 보기’에서 작업 흐름과 담당 계층을 분리해 동시에 표시한다. 각 보기만 선택할 수도 있다.
3. 흐름은 요청→계획→화면 수정/보호 확인 병렬→합류 검토→전달이다. 검토→수정의 재검토선을 따로 둔다.
4. 실패한 시도1→재개한 시도2를 보존하고 시간 이력에서도 구분한다. 모두 화면 예시이지 실제 실행 결과가 아니다.
5. 담당 계층은 조정→실행 대화2개의 업무 인계와 실행→보조 AI 생성을 다른 선·직접 문구로 표시한다.
6. 작업/담당 선택 시 우측 상태·소유 범위·앞선 조건·다음 행동을 바꾼다. 실제 모델·effort는 항상 ‘미확인·미수집’이다.
7. 설정값도 미수집으로 분리한다. 설정·타이틀·시간 근접성으로 실제 관계나 적용값을 추정하지 않는다.
8. 기존 실제 관측 기록은 접힌 별도 영역에 두고 예시 작업과 연결하지 않는다. 손실·보존 경고를 유지한다.
9. 날짜 있는 한국시간·44px 제어·키보드 focus·좁은 화면 분기를 코드에 포함했다. 실제 동작·접근성 PASS는 아니다.

### 기존 Desktop와 별도 App Server는 같은 범위가 아니다

- 현재 제공된 Desktop `list_threads` 계약은 제목·상태·프로젝트 요약을 제공하지만 부모·실제 모델/effort를 보장하지 않는다.
- `read_thread`는 최근 대화/turn 요약을 읽는 도구이며 metadata-only 선택자가 없다. 공식 연결 한정 확인에서는 호출하지 않았다.
- `wait_threads`도 조정용 상태/내용 반환 도구다. viewer 백그라운드 구독 API로 전용할 수 있다고 확정하지 않는다.
- 도구가 이 대화에서 사용 가능해도 plugin Node 서버에서 지속 호출 가능한 API가 생기는 것은 아니다.
- 공식 App Server는 자체 클라이언트를 위한 인터페이스다. `thread/list/read`로 접근 가능한 저장 이력을 읽을 수 있다.
  저장 이력이 자체 생성 대화로만 제한된다고 단정하지 않으며, 기존 Desktop 저장 이력 노출 범위도 아직 미검증이다.
- `thread/read`는 대화를 로드/재개/구독하지 않는다. `thread/status/changed`의 loaded 상태는 해당 서버 문맥이다.
  별도 서버의 notLoaded를 다른 Desktop 서버에서 실행 중이지 않다는 뜻으로 표시하면 안 된다.
- 자체 관리·로드·구독 세션의 이벤트는 후보가 되지만, 이미 열린 Desktop 세션의 실시간 attach와 동일하지 않다.
- 공식 문서는 stdio와 Unix socket을 설명한다. 이것만으로 현재 Desktop endpoint의 공개·접속·metadata 권한이 입증되진 않는다.
  TCP WebSocket은 experimental/unsupported이며 이번 계획의 필수 경로로 채택하지 않는다. socket 탐색·비공개 IPC는 하지 않는다.
- 부모/조상 필터의 experimental capability와 실제 생성 항목 지원은 버전별 확인 대상이다. 현재 설정을 바꾸지 않는다.
- `model/list`·`config/read`·turn 요청 인자만으로 실제 turn의 모델/effort를 확정할 수 없다.
  확정 metadata가 공식 응답에 없다면 전체 요구는 미완료이며, 임의 수집기·숨은 로그 파싱으로 채우지 않는다.

## 데이터·모듈·보호 제안

새 자료를 기존 hook 사건에 억지 추가하지 않는다. 제안 모델은 업무, 명시 인계 관계, 공식 실행 metadata,
기존 사건 참조를 별도로 보유하고 화면에서 연결한다. 각 값에 source/kind/observedAt/host/thread/turn을 보존한다.
확정 응답은 어댑터 입력, 단계는 프로젝트 정본, 선택/접기는 UI 메모리다. 충돌 값은 덮지 않고 범위·시각과 함께 미확인 표시한다.
자유 서술 메시지/preview/prompt/명령/출력/환경변수는 adapter에서 버리고 필드 allowlist만 받는다.
사건의 원래 event ID·후보·시각은 불변이며 task 참조가 없으면 임의로 소급 연결하지 않는다.
node/edge는 안정 ID로 중복 제거하고 고아·순환·다른 host 동명이인은 관계 미확인으로 표시한다.
원래 viewer 인증·Origin/Host 제한·토큰 수명·local-only와 emitter 실패 시 기존 gate 결과 보존을 유지한다.
권한 오류·구독 해제·stale·응답 역전 때 이전 성공을 현재 성공으로 보이지 않게 한다. 과거 기록은 날짜와 함께 열람 가능하다.

예상 영향은 `dashboard/src/app.tsx`·`view-model.ts`·스타일·관련 시험, metadata를 받는 경우 `api.ts`와
서버의 별도 읽기 계약이다. 기존 client 검증·TanStack 조회를 재사용한다. 실제 provider를 고른 뒤 최소 파일 책임을 정한다.
생성 정적 asset은 root dashboard에서만 제작한다. 제품 적용 때 두 manifest·README·변경 안내의 버전 정책을 적용한다.
지금은 정적 시안과 관련 기록만 바꾸므로 버전·제품 생성물·플러그인 코드를 변경하지 않는다.
