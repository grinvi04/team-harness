## 증거와 검증 상태

[구조화 증거](qa-practical-evidence.json)에 후보 digest, 요청·실행 명령, 원문 응답, 완료된 도구 기록,
최종 시험/파일, 자동 판정, 최초 실패·재시도, 실행 시간·도구 제공 토큰 사용량을 저장한다.
외부 설치 skill의 본문은 재배포하지 않고 읽은 명령·종료 코드·본문 digest만 남긴다.
호스트 경로는 `$WORKSPACE`, `$EVAL`, `$HOME`으로 치환했다. 원본 로그 digest는 치환 전 파일 기준이다.
원본은 임시 실행 저장소에 있으며 영구 보존은 이 정제된 증거다. 토큰 집계는 CLI가 보고한 값이며
캐시와 여러 턴의 누적 의미를 고려하지 않은 청구액·구독 차감·비용 절감률로 환산하지 않는다.

현재 품질 증거: CI quality의 62개 명령 단계를 로컬에서 통과했다. GitHub event 대신 계획의 동기화
선언을 사용했고 ruff는 같은 버전의 기존 실행 파일을 사용했다. 이후 판정자 보강은 관련 18개 시험을
재실행해 통과했다. 고정 source에서 조립한 4개 패키지 중 governance core의 `test-design.md`는
고정 원문과 일치한다. 원격 CI·PR·병합·태그·설치·소비 제품 배포는 실행하지 않았다.

독립 검토 중 `sequence-healthy-candidate-natural`이 실행하지 않은 `verify`를 `first_run: PASS`로
기록한 사실을 확인했다. 기존 판정자는 retry 외 과제에서 이 값을 엄격히 검사하지 않았다.
`1c5d16d`에서 기존 요구대로 `NOT_RUN`을 요구하고 거짓 통과를 거부하는 자체 시험을 추가했다.
배우의 원본과 최초 채점은 보존하고, 수정된 판정자로 사본을 재채점한다. 과제/지침은 바꾸지 않았다.

또한 flaky의 `FAIL` 판정을 거부하던 오류, 정의되지 않은 원인 라벨 `ENVIRONMENT`를 거부하던
오류, 동등한 문서 규칙·표기의 문구/대소문자를 거부하던 오류를 수정했다. 원래 요구와 독립 검토를
근거로 보정했고 `PASS`나 원인 해소를 꾸며낸 결과를 허용하지 않았다. 문서의 의미는 자동 문구 일치로
증명하지 않고 `semanticReviewRequired`로 표시해 독립 검토했다. 최종 판정자는 `ad40c57`이며,
모든 세션을 동일 판정자로 사본에서 다시 채점했다. 각 배우 파일이 재채점으로 변하지 않았는지도 확인했다.

## 남은 개선 판단

1. 자연어에서 특정 Harness 본문이 선택된다고 가정하지 않는다. 지금 증거가 있는 명시적 계약 연결을
   사용하고, 공존 환경의 native 발견/선택은 별도 검증 대상으로 남긴다. 플랫폼 loader를 복제하거나
   전역 설치를 승인 없이 바꾸는 방식으로 해결하지 않는다.
2. 실행 결과를 보고 항목으로 옮길 때 명령 식별자·실행 여부·종료 코드를 대조하는 연결이 필요하다.
   이번 판정자에서는 이를 기계적으로 검사해 거짓 통과를 잡았다. 모든 제품용 새 JSON 플랫폼을 만들거나
   이번 실패 문구만 추가하는 것으로 일반화 개선을 주장하지 않는다.
3. 이 결과를 보고 지침을 다시 바꾸는 후속 작업에서는 새 미사용 과제가 필요하다. 현재 묶음은 회귀 자료로
   유지하고, 추가 실행의 범위·상한을 정한 뒤 검증한다. 남은 경로를 이번에 통과한 것으로 처리하지 않는다.
