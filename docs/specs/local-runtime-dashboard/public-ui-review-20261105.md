## 우선 고칠 다섯 가지

1. **업무 상태와 연결 상태가 섞인다.** ‘결과 확인 중’ 옆 ‘정보만 따로 받을 수 없음’은 서로 다른 대상이다.
   업무에는 담당·진행·기다리는 대상·해제 조건을, 연결에는 마지막 확인·수집 범위·미확인 사유를 둔다. 예시와 실제 기록의 경계도 유지한다.
2. **일방향 단계가 실제 일을 과도하게 단순화한다.** 병렬 담당 둘, 검토 후 재수정, 실패 뒤 재개가 보이지 않는다.
   중앙 다이어그램에서 ‘일의 흐름 / 담당 관계’ 두 보기를 명확히 선택한다. 병렬 노드·재검토·재개를 유지하고 근거가 없는 선은 그리지 않는다.
3. **‘다음 행동’이 행동을 정하지 못한다.** ‘보여줄 방법을 다시 골라요’에는 결정할 사람과 선택 후 결과가 없다.
   ‘사용자 결정 대기 · 표시 범위 선택 → 선택한 범위의 화면안 확정’처럼 주체·행동·기다림 해제 조건을 쓴다. 이는 문구 예시이며 실제 상태가 아니다.
4. **설명과 AI 미확인이 핵심 업무보다 무겁다.** 담당마다 같은 경고를 반복하고 큰 정보 칸 두 개도 미확인이다.
   상단 다섯 카드는 업무명/담당/상태 요약과 막힘/다음 행동 두 줄로 압축한다. AI 모델·effort와 미수집 사유는 선택 상세에 항상 명시하고 긴 근거만 접는다.
5. **쉬운 말과 정확성이 아직 균형을 이루지 못했다.** 긴 질문형 문구·반복 설명은 읽는 양을 늘리고 ‘생각하는 깊이’는 강도를 확정한 듯 읽힐 수 있다.
   ‘담당’, ‘진행’, ‘검토 대기’, ‘다음 행동’, ‘AI 설정’처럼 짧고 전문적인 일상어를 쓴다. 실제 추론 수준은 설정과 분리하며 미수집을 숨기지 않는다.
   한국시간은 사건 상세에 초·필요 시 밀리초까지 제공한다. 좁은 화면·확대·키보드는 후속 인수에서 직접 확인해야 한다.

## 유지할 점과 추천 구조

유지: 흐름과 관계를 설명하는 선 이름, 예시 표시, 설정/실제 구분, 과거 사건과 현재 상태 분리,
한국시간, 손실/보존 경고, 기존 읽기 전용·인증·Host/Origin·원문 제외 계약이다.

추천 구조는 **간결한 작업 탐색 → 선택 작업 요약·막힘·다음 행동 → 중앙 다이어그램 → 선택 상세·보조 시간 흐름 → 연결된 증거**다.
원래 요구인 ‘작업 흐름·담당/서브에이전트 계층을 한눈에 보는 다이어그램’을 기본 화면의 중심에 유지한다. 목록/상세 사례만으로 이 목표를 대체하지 않는다.
중앙의 ‘일의 흐름’은 작업 의존·병렬·재검토·실패 뒤 재개를, ‘담당 관계’는 명시 인계와 native 생성 계층을 보여준다. 두 보기에서 선택 작업을 유지한다.
작업 의존선과 담당 계층선을 같은 선으로 합치지 않고 직접 이름을 붙인다. 선택한 작업·현재 가지에 초점을 맞추고 다른 가지를 접어 전체 그래프 과밀을 줄인다.
넓은 화면의 간결한 탐색/상세는 중앙 그림을 보조한다. 좁은 화면도 선택한 작업의 그림을 유지하며 대체 목록과 펼침 순서는 실제 인수에서 확인한다.
관계 종류·출처·확인 시각과 선택 담당의 모델·effort/미수집 사유를 명시한다. 긴 기술 ID·원문 UTC·설정/실제 적용의 상세 근거만 접는다.
인과관계가 없는 과거 훅 사건은 ‘연결되지 않은 기록’에 둔다. 시간 근접성만으로 담당 업무의 결과로 묶지 않는다.
