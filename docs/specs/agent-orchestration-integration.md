# Agent Orchestration의 필요한 부분만 통합

상태: 선택 통합 구현·로컬 품질·독립 검토 완료, 원격 PR gate 단계. [PR #447](https://github.com/grinvi04/team-harness/pull/447).

## 목표와 판단

여러 개발자가 LLM으로 제품을 개발할 때 필요한 공통 기준·인계·검증·재개를 Team Harness에서 제공한다.
2026-09-20 사용자는 기존 Agent Orchestration을 그대로 옮기지 말고 필요한 것만 통합하며 잘못된 부분은 수정하거나
삭제하도록 명확히 했다. 이전 36e59bd의 테스트 통과는 원래 패키지의 기능 보존 증거이지 도입 필요성의 증거가 아니다.

| 대상 | 판단·근거 |
| --- | --- |
| 목표·완료 조건, 담당 범위, 후보·검증 근거, 다음 행동 | 유지: 다른 개발자나 세션이 실제 작업을 이어갈 때 필요 |
| ao-coordinate | 수정: 짧은 인계·재개 지침으로 한정하고 기존 workflow를 중복 실행하지 않음 |
| JSON schema·4개 검사기·npm 패키지 | 제거: 제출된 선언 비교가 실제 실행·권한·품질을 보장하지 않으며 현재 소비 흐름에 별도 기계 API 수요가 없음 |
| 작업 기록 생성 CLI | 제거: 기존 이슈·PR·스펙으로 충분하며 새 문서/상태의 중복을 유발 |
| 연구용 역할·상태 기계·budget/epoch/권한 매핑 명세 | 제거: 실제 플랫폼 계약과 기존 Harness 정책으로 판단; 수동 선언을 실행 준비의 증거로 삼지 않음 |
| 모든 위임의 기술적 권한 제한 전제 | 수정: 작업에 실제로 필수인 제한은 확인하되 과거 시험 조건을 일반 작업에 강제하지 않음 |
| 기존 품질·권한·리뷰 gate와 제품 기록 | 유지: 선택 통합을 이유로 약화·삭제하지 않음 |

시작점: Team Harness develop 9572066. 원본 AO 4004bd4와 통합 초안 36e59bd는 Git에 보존한다.
이전 AO 저장소의 실험/태그/원본 소스는 보존용이며 새 배포에 포함하지 않는다.

## 수용 기준과 작업

1. [작업] 독립 도구를 제거하고 skill을 필요한 절차로 축소 → 검증: 실제 workflow 배포물의 독립 사용·참조 및 core 비의존 검사.
2. [작업] 관련 현재 문서·catalog·CI와 불필요했던 스택 탐지 예외 정리 → 검증: 현재 참조/형식 검사, 기존 전체 quality 검사.
3. [작업] 소비 제품의 불필요한 개발 의존성 제거 → 검증: 제품 앱·데이터·과거 증거 지문 불변, 루트 도구 의존성과 설치 명령 제거.
4. [작업] 원래 요구로 독립 재검토 → 검증: 고정 후보에서 과잉 절차·누락된 필수 검증·끊긴 소비 경로 검토.

초기 npm 통합 테스트는 선택 workflow 배포 경계 검사로 대체한다. 모듈 탐지 예외 때문에 추가했던 fixture도 함께 제거하고 repo-sync 테스트는 develop 원본으로 복구한다.
기존 core·권한·리뷰·품질 테스트를 유지한다. 모듈만 위해 추가했던 self-repo 예외는 원래 동작으로 복구한다.
삭제되는 모듈 전용 테스트는 제거되는 기능의 검사이며 실패를 숨기기 위해 기존 core 테스트를 없애지 않는다.
