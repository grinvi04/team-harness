# 진행 문서 동기화 검사

## 목표·승인 범위

2026-09-23 사용자 요청: 진행 문서 동기화 누락을 기존 로컬 검사·PR CI 계약에 연결하고,
최소 구현·검증·문서 현행화·기존 게이트를 통한 develop 병합까지 진행한다. 최초 구현 범위에서는 릴리즈·설치·전역 변경을 제외했다.
제품 방향 판정은 **소유**(문서와 증거의 연결 검사)다. 일반 의미 판정·실행 엔진·중앙 상태 저장소는 만들지 않는다.

## 최소 설계

기존 작업 스펙 또는 PR 본문에 `harness-doc-sync` JSON fence 하나를 둔다. PR은 스펙의 경로만 가리킬 수도 있다.
별도 등록부·상태 파일 없이 기존 기록을 사용하며, 과거 모든 문서를 지속 검사하지 않고 현재 작업의 선언만 검사한다.

- `documents`: 갱신·대조한 저장소 상대 문서 경로와 사유. 미선언 문서 발견과 사유의 적절성은 리뷰 책임이다.
- `items`: 연결한 문서의 고유한 체크박스 문구, `done/pending/deferred`, 근거와 다음 행동/재개 조건.
  해당 항목만 상태를 대조한다. 재사용 체크리스트·역사적 기록은 documents에 사유와 함께 연결하고 items로 선언하지 않는다.
- 완료 근거는 현재 파일의 SHA-256 또는 정확한 Git 태그와 포함되어야 할 전체 commit SHA다.
  파일 digest는 근거 변경을 검출할 뿐 내용의 진실·시험 실행 여부를 증명하지 않는다.
  특정 태그를 기다리는 항목은 그 태그가 이미 존재하면 실패한다. 후속 릴리즈는 다른 정확한 태그를 사용한다.
- 문서 영향이 없으면 `noImpact` 사유로 선언한다. 자동 비적용 추정은 하지 않는다.
- 로컬 CLI와 이 repo의 기존 `quality` 잡에서 같은 checker를 실행한다. PR 본문 편집도 CI를 다시 실행한다.
  소비 repo는 설치된 plugin의 CLI 또는 검토해 복사한 checker를 기존 검사에 연결한다. 기존 repo에 자동 적용하지 않는다.

## 수용 조건과 검사

1. 정상 완료·실제 미완료·조건부 보류·후속 릴리즈·재사용 서식은 허용한다.
2. 선언 없음/빈 선언, 문서·근거 누락, 중복 또는 없는 체크박스, 완료와 미체크 모순,
   파일 근거 digest 불일치, 재개 조건 누락, 발행된 태그에 대한 대기는 거부한다.
3. 태그 근거가 완료 후보를 포함하지 않거나 Git 조회가 실패하면 통과시키지 않는다.
   로컬 태그만 읽으므로 최신 원격 여부는 별도 fetch/담당자 확인이며 자동 네트워크 호출은 하지 않는다.
4. PR 생성 시 선언한 파일은 HEAD와 일치해야 한다. 독립 검토에서 확인한 untracked 누락과 들여쓴 코드
   예시 오탐을 회귀 검사한다. 선언 대상 체크박스는 앞 공백 0–3개로 제한한다.
5. 저장소 밖 경로·symlink·임의 명령 실행을 허용하지 않는다. JSON은 데이터로만 읽는다.
6. 실제 변경에서 대상 문서를 빠뜨리거나 의미가 모순인 경우는 독립 검토로 확인한다.

검사: `node --test tests/document-sync-test.mjs`, 기존 `.github/workflows/ci-gate.yml` quality 전체,
고정 후보의 독립 문서·구현 검토. 선언이 없는 과거 문서 전수 자동 판정은 수용 기준이 아니다.
