# feature-add — 신규 기능의 프로젝트 연결

일반 구현·TDD는 선택한 Superpowers의 test-driven-development/실행 스킬 또는 native 방법론 하나를 따른다.
먼저 [공통 프로젝트 계약](../ao-coordinate/project-contract.md)을 읽고 현재 구현에 연결한다.
별도의 설계·승인·RED/GREEN 루프를 다시 시작하지 않는다.

## 신규 동작의 경계

승인된 요구와 직접 소비자에서 새로 생기는 결과·오류·인가·상태 변화를 검사에 연결한다.
기존 동작 변경이 중심이면 feature-modify, 중요한 미결정이 있으면 plan 계약의 필요한 부분만 적용한다.
기존 승인·계획·작업 브랜치를 재사용하며 새 feature 진입에는 승인된 spec이 필요하다.

공개 결과를 단언하는 RED를 확인하고 검수한 spec/test를 잠근 뒤 구현한다.
현재 담당자가 신규 동작과 직접 소비자의 회귀, 제품 전체 품질 검사·필수 독립 검증을 확인한다.
문서·설정·순수 비주얼은 적합한 검사로 확인하며 테스트 개수나 무관한 E2E를 강제하지 않는다.
완료 증거·문서 현행화·승인된 커밋과 다음 delivery는 공통 계약을 따른다.
