# 한국어 UI/UX 표준 (한국 서비스·한국어 화면 전용)

[표준 적용 기준](standards-scope.md)을 따른다. 한국어 화면에만 적용하며 제품의 독자·용어·톤을 우선한다.
특정 업무 시스템·커머스의 화면 구성을 모든 서비스에 강제하지 않는다.
배포용 안내는 `templates/rules/korean-ux.md`다.

## 1. 마이크로카피 톤

쉽고 일관된 문장을 쓴다. 해요체·합니다체는 독자와 제품의 톤에 맞춰 선택한다.
버튼은 결과를 예상할 수 있는 짧은 행동 이름으로 쓴다. 실패 안내에는 가능한 다음 행동을 붙인다.
삭제 경고는 실제 복구 가능성에 맞춘다. 복원 가능한 삭제에 “되돌릴 수 없어요”라고 쓰지 않는다.
빈 상태는 항목 없음과 조회 실패를 구분한다.

## 2. 용어

| 의미 | 표현 예시 | 확인할 것 |
|---|---|---|
| 로그인 식별자 | 아이디 | 사람의 이름과 구분 |
| 사람의 이름 | 이름·표시 이름 | 로그인 ID로 바꾸지 않음 |
| 결제 요청 문서 | 청구서 | 세금계산서와 같은 문서인지 제품에서 확인 |
| 로그인·로그아웃 | 로그인·로그아웃 | 익숙한 용어 사용 |
| 개인 설정 영역 | 내 정보·마이페이지·프로필 | 실제 기능과 일치 |

영어를 기계적으로 번역하지 않는다. 같은 단어라도 의미가 다른 문서를 하나의 용어로 합치지 않는다.
업무 용어집은 해당 프로젝트에서 관리한다.

## 3. 폼·데이터 포맷

수집할 정보와 지원 사용자를 먼저 정한다. 이름·전화번호·주소의 형식을 국내 개인 사용자로 한정하지 않는다.
국내 전용 검증과 국제 형식을 구분하고 서버·화면의 허용 범위를 맞춘다.
날짜·시각은 사용자 시간대와 목적에 맞게 표시하고 전송 계약과 구분한다.
금액은 통화·단위·소수 자릿수·반올림을 [금액 계약](db-standards.md#금액-저장전송-계약)에 맞춘다.
화면에서 원 단위로 표시하는 선택이 내부 계산·API 정밀도를 바꾸지는 않는다.
원문·정확한 값이 필요하면 축약 표시와 구분해 제공한다.

## 4. 화면 관행과 검증

버튼 위치·토스트 위치·화면 밀도·필터·합계 행은 제품의 작업 흐름과 사용자 시험으로 정한다.
정보가 많은 업무 화면과 간단한 입력 화면에 같은 밀도를 강제하지 않는다.
숫자 비교에는 정렬·단위를 일관되게 쓰고 색만으로 상태를 전달하지 않는다.
오류·삭제·권한 거부 문구가 실제 동작과 일치하는지 확인한다.
키보드·초점·좁은 화면·확대 시의 읽기와 조작은 [디자인 검증](frontend-design-standards.md#8-검증-pr-전-프레임워크-무관)을 따른다.
