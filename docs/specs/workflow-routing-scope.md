# 라우팅 안내의 요청 범위 수정

2026-10-11 사용자 승인: 미병합 브랜치의 유효한 수정만 최신 develop에 반영하고 검증·병합한다.
제품 방향 판정은 **연결**이다. 일반 요청의 의미와 대화 연속성은 native agent에 위임한다.

## 문제와 변경 범위

현재 라우터는 `정리해줘`와 과거 spec 파일만으로 기능 추가를 제안한다.
열린 PR이 있으면 `구현해줘`에도 병합 절차를 제안한다. 후보 안내의 오류이며 실행 승인 증거는 아니다.
옛 `fix/astra-workflow-scope` 전체를 병합하지 않고 아래 계약만 반영한다.
현재 검증 증거 재사용 계약·후보 안내문·GitHub 보호와 delivery wrapper는 유지한다.

## 수용 기준과 확인

| ID | 조건과 기대 결과 | 필수 검사 |
|---|---|---|
| route-scope | 일반·복합·인용·부정·질문 요청과 비문자 입력에는 후보를 주입하지 않는다 | Node 순수 함수·실제 훅 입력 |
| route-implement | 명시한 짧은 구현 요청과 main/develop+spec+열린 PR 없음에만 feature-add를 제안한다 | 상태 조합·native loader |
| route-integrate | 명시한 짧은 병합 요청에 기존 PR 게이트를 제안한다. PR이 없으면 커밋된 feature/fix/codex만 feature-merge를 제안한다 | 상태 조합·기존 보호 조회 검사 |
| route-preserve | 후보는 승인이 아니다. 훅 JSON·fail-open·PR base 보호 조회·develop 기준 커밋 판정과 기존 가드는 유지한다 | 기존 회귀·CI quality 전체·독립 읽기 전용 검토 |

명시 요청 예시는 `구현해줘`, `implement it`, `머지해줘`, `merge it`이다.
`진행해`도 대화의 기존 목표·승인에 따라 계속 처리한다. 훅이 후보를 주입하지 않아도 작업을 막지 않는다.
spec 존재는 현재 요구나 사람 승인을 증명하지 않는다. 후보를 적용하기 전에 원본과 대조한다.

## 전달과 완료 경계

변경 시험 RED와 유지 시험 PASS를 확인한 뒤 계약을 잠그고 구현한다.
소스 버전은 동작 변경 규약에 따라 0.89.0으로 올린다. 현재 설치·발행 0.88.0과 구분한다.
검사·독립 검토·develop PR 병합이 이번 구현의 완료 조건이다. 병합 상태는 연결 PR에서 확인한다.
복구 묶음 검증 뒤 옛 로컬 브랜치와 사용하지 않는 원격 문서 브랜치를 정리한다.
현재 checkout은 사용자 선택에 따라 codex/develop-local로 유지하고 d1f9 작업공간은 보존한다.
main 릴리즈·태그·설치·소비 원격·배포·결제와 Claude 인증·실제 모델 검증은 이번 범위 밖이다.
