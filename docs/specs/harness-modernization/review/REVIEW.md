# Team Harness 재검토 — 수정 전 판단 자료

검토일: 2026-10-09 KST. 이 결과는 선언한 범위의 파일·코드 검토와 격리 시험이다.
모든 실행 경로의 검증 또는 수정 완료를 뜻하지 않는다. 남은 실행 검증은 아래에 구분했다.

원본 코드·문서·전역 설정·소비 프로젝트는 변경하지 않았다. 기존 `.gitignore` 변경을 보존했다.
아래 보고서와 시험 결과는 임시 폴더에만 저장했다. 커밋·PR·배포·실제 보호 설정 변경은 없었다.

## 결론

199줄 상한과 문서 계층화는 가능하다. 그러나 문서부터 기계적으로 나누는 순서는 적절하지 않다.
안전 검사에서 실제 놓치는 입력, 검증 후보를 묶지 못하는 경계, 현재 코드와 충돌하는 지침을 먼저 처리해야 한다.
문서 경로·제목을 읽는 패키징·지도·테스트·생성기도 문서 재구성과 함께 변경해야 한다.
기존 시험 통과가 이러한 문제의 부재를 보장하지 않는다는 반례를 확보했다.

## 중요한 발견

| 항목 | 판정 | 확인한 범위 |
|---|---|---|
| 보호 설정 적용 실패 | 재현 | 검사 조회 실패 뒤 가짜 API의 필수 검사 설정이 null로 바뀌고 명령은 실패했다. |
| 비밀 파일 전송·로컬 삭제 가드 | 재현 | curl/wget의 일부 파일 입력과 절대 경로 git/rm 명령을 허용했다. 명령 자체는 실행하지 않았다. |
| 파괴적 마이그레이션 검사 | 재현 | Python 한 줄 함수, Ruby 탭, SQL COLUMN 생략, ORM 실행 주석을 놓쳤다. |
| 네이티브 검증 후보 | 정적 확인 | smoke 실행 파일, 원본 파일 바이트, 보고서 쓰기 시점·경로가 한 후보로 충분히 묶이지 않는다. |
| 검증·완료 판정 | 코드·순수 함수 확인 | 불확실한 리뷰를 기각으로 세거나 복구 확인·테스트 수 판정이 실제 계약을 확인하지 못한다. |
| 문서 재구성의 직접 소비자 | 순수 파서 반례 | 제목·본문을 바꾸면 프로젝트 지도 파서가 실패한다. 패키징·CI도 기존 경로·본문에 의존한다. |
| 소비 지침 | 현재 원본 대조 | ERP의 테넌트 설명, DriveTree QA·DB 시험 규칙, siku의 스택 규칙 등이 현재 구현과 맞지 않는다. |
| 전역 실행 허용 규칙 | 정책 판정 재현 | 넓은 git push·gh api 규칙은 강제 push·보호 설정 삭제 명령에도 allow를 반환한다. |

현재 GitHub의 다섯 저장소 main/develop 보호 설정은 모두 존재한다.
따라서 도구의 실패 처리 문제를 현재 원격 보호가 해제되었거나 실제 데이터가 유출되었다는 주장으로 확대하지 않는다.
전역 allow 판정도 사용자 요청의 권한, 샌드박스, 서버 보호를 대체하지 않는다.

## 검증 결과와 한계

- Harness의 현재 quality 잡 63단계를 격리 사본에서 재현했고 최종 63단계가 통과했다.
- 최초 3개 실패는 조사자가 지정한 로그 환경변수 때문에 발생했다. 해당 변수만 제거해 영향 시험을 재실행했고 최초 결과를 보존했다.
- 추가 구문 검사는 152개, YAML은 83개를 확인했다. YAML 최초 6개 오류는 단일 문서 파서를 사용한 조사 오류였고 다중 문서 파서로 확인했다.
- 실제 시크릿 스캐너는 현재 HEAD의 조상 744커밋에서 탐지 0건이었다. 모든 참조·운영 비밀의 부재를 뜻하지 않는다.
- 현재 원격 main/develop 보호 10건과 ruleset 목록 5건을 조회했다. 원격 CI 실행이나 실제 수정 작업은 하지 않았다.
- 읽기 전용 업무 계약의 독립 검토 두 역할을 사용했다. 실제 권한 강제는 별도 확인 대상이며 역할 설정 확인·모델 품질/비용 비교와 구분한다.

보호 변경, 전송, 삭제, DB 파괴 작업은 실제 서비스에서 실행하지 않았다.
신규 네이티브 세션의 실제 hook dispatch와 최신 Claude 모델 호출은 실행 증거가 부족하다. Codex 세 설정의 좁은 같은 과제 비교는 이후 수행했으며 아래 추가 실행 보고서에 연결했다.
이 중 격리·읽기 전용으로 가능한 시험까지 모두 승인 부족으로 설명하지 않는다. 아직 실행하지 않은 검증도 남아 있다.
소비 앱 전체 QA·배포, 실제 원격 쓰기·운영 파괴 시험은 이번 검토 범위에서 제외한다. 제외 항목을 필수 미확인으로 세지 않는다.
각 사유·남은 증거·재개 조건은 위 전역 추가 보고서에 연결했다. 문서 존재·구문·기존 PASS로 실행 검증을 대신하지 않는다.

## 수정 순서 제안

1. 실제 반례가 있는 실패 처리·차단 누락과 검증 후보 연결을 수정한다.
2. 검사·리뷰·복구·태그 판정과 완료 표현을 수정한다.
3. 현재 코드와 충돌하는 공통·소비 지침, 역사와 정본의 구분을 수정한다.
   폐기·축소 후보는 현재 호출부와 대체 계약을 확인하고 함께 처리하며 유효한 연결·과거 시험은 보존한다.
4. 문서와 직접 소비자를 함께 계층화하고 모든 소유 MD를 199줄 이하로 만든다.
5. 합의된 Sol 6.1 기본·중요한 판단/독립 검증 Astra 방향에서 최신 공식 지침과 같은 과제 비교로 역할 모델·effort를 다시 선정한다.
   Claude 강제 훅·Codex 역할/전역 설정·직접 소비 문서를 함께 수정하고 실제 적용을 확인한다. 새 대화 메모리 생성 입력 중단·기존 조회 유지도 반영한다.
6. 같은 후보에서 영향 검사·필수 CI·독립 검토·문서 동기화를 확인한다. 배포는 별도 범위로 둔다.

이 순서는 제안이다. 이번 요청은 검토까지이므로 위 수정 단계는 시작하지 않았다.

## 최신 실행 계획과 터미널 확인

추가 [사용자 지시 대조](09-user-instruction-audit.md): 발견 57개의 추적과 원래 지시 충족을 구분했다. 원지시 대조·미추적/ignored 소유 MD 기준을 계획에 보완했으며 최신 X 사례와 전체 역할/Claude 비교는 미완료로 유지한다. Codex 세 설정의 좁은 비교 결과는 [agent 담당 추가 실행](10-agent-owned-execution.md)에 연결했다.

사용자 Codex 터미널 업데이트 후 실제 버전은 0.161.0이며 Claude 터미널은 2.1.267이다.
최신 [원본·버전](../planning-source-state.json)과 [안전한 정책 분류 재시험](../planning-execpolicy-probes.json)을 연결했다. 실제 push/보호 삭제는 실행하지 않았다.
[단계별 구현 계획](../plan/README.md)은 안전·판정 → 모델/전역 설정 → 문서/직접 소비자 → 통합 인수 순서다. 각 단계에 파일·수용 기준·필수 시험·미확인의 실행 조건을 연결했다.
이전 수정 순서는 당시 제안이며 실행 시 이 계획의 의존 관계를 적용한다. 계획은 임시 폴더에만 저장했고 원본 수정은 시작하지 않았다.

[착수 준비 추가 확인](11-implementation-readiness.md): 전면 감사를 반복하지 않고 전역 부분 적용/복구·혼합 버전 조건을 계획에 보완했다.
추가 독립 역할의 실제 sandbox는 설정의 read-only와 달리 workspace-write였다. 행동 계약은 지켰으나 쓰기 차단 검증은 미확인이며 고위험 완료 gate에 반영했다.
