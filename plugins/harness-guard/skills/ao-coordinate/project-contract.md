# 일반 방법론에 연결하는 프로젝트 계약

계획·신규 구현·기존 동작 변경·진단에서 공통으로 읽는 정본이다.
Superpowers를 선택했다면 설계·계획·TDD·디버깅은 해당 스킬에서 수행한다.
Harness는 아래 프로젝트 계약만 연결한다. 같은 계획·승인·RED/GREEN을 다시 시작하지 않는다.
미설치면 현재 플랫폼의 native 방식으로 수행하며 새 설치를 강제하지 않는다.

## 시작과 승인 범위

- 실제 제품 루트, AGENTS.md, 관련 stack rule, 요구·직접 소비자·기존 검사와 현재 변경을 확인한다.
  명령과 API는 현재 프로젝트에서 확인하며 존재하지 않는 경로를 추측하지 않는다.
- 기존 계획·승인·작업 브랜치를 재사용한다. 목표·수용 기준·권한을 바꾸는 미결정만 확인한다.
  계획·진단 요청은 구현·커밋·원격 변경·배포 권한을 만들지 않는다.
- 사용자와 다른 작업자의 변경을 보존한다. 충돌할 때 필요한 선택을 확인하며 임의 stash·reset·전환하지 않는다.
- GitHub 하네스의 새 `feature/<name>`에는 승인된 `docs/specs/<name>.md`가 선행한다.
  다른 위치의 상세 계획은 링크해도 된다. 파일 존재는 승인 증거가 아니며 trivial 면제는 실제 자명한 변경만 해당한다.
  로컬 전용 제품에 원격·공개·PR을 강제하지 않는다.

## 프론트엔드 설계 연결

프론트엔드의 업무 흐름·데이터·상태·구조를 설계하거나 변경할 때만 [프론트엔드 계약](frontend-contract.md)을 읽는다.
프론트 없는 작업에는 적용하지 않으며, 작은 문구·스타일 변경은 영향 항목만 확인한다.

## 테스트와 검증 계약

- 구현·시험 전에 [검증 계약](../verification-before-completion/SKILL.md)을 읽어 요구·위험별 범위와 증거에 연결한다.
  이미 읽은 현재 계약과 선택한 방법론의 검사는 재사용한다.
- 동작 변경은 원래 증상/미구현 때문에 실패하는 RED와 유지할 동작의 PASS를 확인한다.
  방법론에서 검수한 재현·테스트를 다시 만들지 않는다. 문법/import 오류나 약한 단언은 RED 증거가 아니다.
- 검수한 spec/test를 잠근다. 구현자는 수정·삭제·약화·skip으로 통과시키지 않는다.
  계약 오류는 원래 요구와 근거를 계약 소유자에게 돌려 정정·재검수한다.
- 현재 담당자가 요구·통합·Git 결과를 책임진다. 필요하고 허용된 위임만 실제 플랫폼에서 수행하며
  소유 파일·잠긴 계약·검사·중단 조건을 전달한다. 필수 독립 검증자는 구현에 참여하지 않는다.
- 수정은 요청 범위에 한정한다. 같은 실패를 새 증거·가설·환경 변화 없이 반복하지 않는다.
  환경·인증 문제를 모델 변경이나 권한 우회로 해결하지 않는다.
- 검증 명령이 자동 생성·삭제하는 로그·캐시·임시 파일도 쓰기 범위에 포함한다. 별도 저장이
  허용되지 않았다면 명령 출력으로 증거를 전달하고, 실행 전후 실제 파일 변화까지 확인한다.
  no-log 조건에서 npm의 `logs-max=0`만 지정하면 기존 로그가 삭제될 수 있으므로 단독 처방하지 않는다.
  Unix의 npm 예는 `npm_config_logs_max=0 npm_config_logs_dir=/dev/null npm_config_update_notifier=false`
  를 실제 제품 검사에만 적용하는 것이다. 현재 호스트·버전에서 새 로그 없음·기존 파일 보존과
  실패 exit code 유지를 확인한다. 다른 도구·호스트도 원본의 쓰기 동작을 확인하고 전역 설정은 바꾸지 않는다.

## 완료와 다음 단계

- 현재 후보·관련 환경·범위에 맞는 증거는 재사용한다. 변경·드리프트·새 실패·미해결 우려 또는
  CI/리뷰의 신선도 조건이 있으면 영향 검사를 다시 실행한다.
- 수용 기준·전체 품질 명령·필수 독립 검증과 잠긴 테스트의 보존을 확인한다.
  필수 FAIL/UNVERIFIED는 완료를 막는다. 실제 비적용만 이유를 적어 SKIP한다.
- 관련 로드맵·체크리스트·스펙·진행·사용 안내를 같은 작업에서 현행화한다.
  과거 실행과 실패는 당시 후보로 보존하고 현재 결과로 연결한다.
- 승인된 Git 범위에서 제품 커밋 규약을 따른다. PR·머지가 이미 승인됐으면 현재 delivery 계약과
  wrapper·리뷰·CI·사람 승인 요건을 그대로 이어간다. 로컬 구현·병합·릴리즈·설치·배포 상태를 구분한다.
  목표를 충족하면 종료하며 새 개선을 임의로 추가하지 않는다.
