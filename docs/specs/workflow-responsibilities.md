# 개발 방법론과 프로젝트 계약의 역할 정리

상태: 구현·로컬 샘플 검사 완료, 독립 검토·통합 진행 중. 현재 순서는 [제품 방향](../product-direction.md),
배포 진행은 [이슈 #469](https://github.com/grinvi04/team-harness/issues/469)가 소유한다.
릴리즈·설치 상태는 [태그](https://github.com/grinvi04/team-harness/tags)와 호스트에서 별도로 확인한다.

## 목표와 범위

개발자는 스킬 명령을 외우지 않고 요구를 설명한다. 일반 설계·TDD·디버깅 방법은 사용자가 선택한
방법론 하나가 맡고, Team Harness는 프로젝트 기준·검사·인계·GitHub 완료 조건을 연결한다.
설치된 Superpowers가 있는 현재 사용 환경에서는 이를 일반 방법론으로 사용하되, 없는 환경에는
설치를 강제하지 않고 native 작업 방식으로 같은 프로젝트 계약을 지킨다.
판정은 일반 방법론 **위임**, 프로젝트 기준·증거·delivery **소유**, 두 경계의 사용 흐름 **연결**이다.

기존 17개 스킬 이름과 명시 호출을 보존하고 plan·feature-add·feature-modify·systematic-debugging의
중복 절차를 축소한다. 완료 검증은 현재 후보·범위·환경의 증거를 연결하고 같은 검사를 이유 없이
반복하지 않는다. 관련 문서·wrapper·프로젝트 지침을 함께 맞춘다.
키워드 라우터 확대, 새 만능 스킬·실행 엔진·의존성, 전역 모델 변경, 외부 스킬 수정·설치,
Stagehand 도입, 샘플의 GitHub 공개·운영 변경은 하지 않는다.

## 수용 기준

- **AC-1 역할:** 일반 방법론을 하나만 선택한다. Harness 연결은 별도 계획·승인·TDD 루프를 재시작하지
  않는다. 기존 승인과 유효한 계획을 재사용하며 중요한 미결정·새 권한만 확인한다.
- **AC-2 자연어:** 일반 요청→적절한 방법론/프로젝트 계약의 예시와 짧은 선택 안내를 제공한다.
  명령어는 선택 사항이다. 질문·진단을 구현·Git·배포 승인으로 바꾸지 않고 Superpowers 미설치에도
  프로젝트 지침·검사로 작업할 수 있다. native 선택과 route-intent의 상태 안내를 구분한다.
- **AC-3 보호:** 현재 수용 기준·테스트 무결성·진단의 무수정 경계·필수 독립 검증·문서 현행화와
  PR/CI/승인/릴리즈 게이트를 보존한다. 로컬 전용 프로젝트에 GitHub를 강제하지 않는다.
- **AC-4 증거:** 같은 후보·관련 환경·검사 범위의 실행 증거는 재사용한다. 변경·새 실패·미해결 우려나
  gate의 신선도 조건이 있으면 해당 검사를 수행한다. 파일 존재·정적 문구 검사를 자동 선택의 성공으로
  보고하지 않는다.
- **AC-5 실제 사용:** 기존 로컬 샘플에서 유용한 작은 기능 또는 결함 하나를 처리한다. 원래 제품 테스트를
  재사용해 정상·실패·경계를 확인하며 원격과 데이터를 보존한다. 자연어 요청의 선택·인계 기록은 실제로
  관찰한 범위만 남기고 모든 미래 요청이나 모델의 선택을 보장하지 않는다.
- **AC-6 배포·문서:** 직접 소비 문서·metadata·버전과 진행 기록을 동기화한다. 기존 품질 검사와 독립
  내용 검토를 통과하고 source/병합/릴리즈/설치를 구분한다.

## 검증과 진행

스킬 본문은 문장을 그대로 단언하는 새 테스트를 만들지 않고 기존 발견성·wrapper·배포 검사와 독립
내용 검토로 확인한다. 변경된 방법론 선택의 의미는 실제 샘플 작업으로 확인한다. 기존 guard·라우터·CI
실행 코드는 그대로 유지한다. 과거 검증 기록은 당시 증거로 보존한다.

- [x] 승인 범위·역할 경계·기존 소비자 확인
- [x] 스킬·wrapper·현재 사용 안내·버전 현행화
- [ ] 로컬 샘플의 실제 작업·검사·문서 현행화 — 전체 검사 통과, 독립 인수 기록 대기
- [ ] 전체 품질·독립 검토·PR 통합
- [ ] 정식 릴리즈·설치 갱신 및 현재 상태 확인
