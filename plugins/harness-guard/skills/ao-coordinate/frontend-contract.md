# 프론트엔드 작업의 조건부 계약

## 프론트엔드 설계 연결

프론트엔드의 업무 흐름·데이터·상태·구조를 설계하거나 바꾸는 작업에서 아래 관련 항목을
기존 계획·스펙·이슈에 연결한다. 이미 정해진 판단은 원본을 참조한다. 작은 문구·스타일 변경은
영향 항목만 확인하고, 프론트 없는 작업에는 적용하지 않는다. 별도 설계·승인·QA 루프를 만들지 않는다.

1. **업무:** 사용자의 판단·행동·완료 결과에서 화면과 데이터 흐름을 도출한다.
2. **기존 연결:** 유사 화면·공통 컴포넌트·데이터 접근·직접 소비자를 확인하고 재사용·변경 이유를 설명한다.
3. **값과 상태:** 서버 확정값·편집 초안·화면 상태·파생값의 소유자와 수명, 저장·취소·실패 처리를 정한다.
   승인 시점 값과 현재 계산값의 의미를 보존하며 관련 충돌·응답 유실 처리는 실제 API 계약에 연결한다.
4. **책임 경계:** 컴포넌트·훅·모듈의 분리가 현재 해결하는 문제와 의존 방향을 설명한다.
   제품의 기존 구조를 출발점으로 삼고 특정 폴더·계층 수·새 의존성을 기본값으로 강제하지 않는다.
5. **재사용과 화면:** 공통 동작과 시각 요소의 재사용을 구분한다. 실제 반복·변경 이유를 근거로 범위를 정하고
   정보 우선순위·밀도·상태 피드백을 제품의 기존 디자인과 맞춘다.
6. **검증 연결:** 변경에 필요한 정상·실패·경계의 업무 흐름과 직접 소비자 결과를 기존 QA 범위에 연결한다.
   정적 검사·렌더 스모크만으로 저장 정합성·사용성·미학을 통과 처리하지 않는다.

핵심 기준은 이 설치된 계약만으로 적용한다. 상세 설명은 소비 프로젝트의 표준 읽기 경로에서
`frontend-engineering.md`를 조회할 수 있을 때 참고한다. 제품별 판단·검사 코드는 제품에 남긴다.
